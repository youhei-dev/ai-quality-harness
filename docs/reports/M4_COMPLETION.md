## 5. 決めたこと

- **DB を持たない**（ADR-0034）: `node:sqlite`・JSON Lines は使わず、`history/*.json` を毎回読み取りだけで集計する。再検討の条件は ADR-0034 の K
- **出す欄を限る**（ADR-0034 の F、人間の決定 D6・Q2）: 数・状態・名前だけを出す。check の出力（tail）・コマンド・`cwd`・絶対パス・`errorSummary`・`parsed.items` の名前（allow のルールの名前を含む）・branch・commit・説明・`parsed.reason` は、読まず、出さない。`--from` はパスではなく指定の順の番号（`#1`）
- **履歴は信頼しない入力**（ADR-0034 の C・D）: 1 ファイル 8 MiB・名前 256 バイト・1 run の check 256 個・数は 0 以上の安全な整数などの個別の上限を超えたものは、切り詰めずに読めないものとして一覧に出す（C）。合わせて 10,000 ファイル・256 MiB の全体の上限を超えたら、入力の誤り（終了コード 2、集計を出さない。D）。ディレクトリの差し替えは検出だけ（防止ではない）
- **設定のハッシュは記録で、固定ではない**（ADR-0033、人間の決定 D10）: 期待の値を同じリポジトリに置くと、同じ pull request で変えられるため。品質ポリシーの変更の別承認は docs の手順（`docs/ops/policy-change.md`）で、aiqh は強制しない
- **出力の上限は、実際に書くバイト**（ADR-0034 の H・N、ADR-0035 の決定 5）: 端末・`--json`・HTML のファイルのそれぞれに 32 MiB。標準出力に実際に書くバイト（各行と改行、文書と改行）と、書くファイルの全部のバイトで判定し、超えたら何も書かない（v0.11.2・v0.12.0）
- **静的 HTML**（ADR-0035）: script・外の資源・イベントの属性を置かない。CSP の meta（固定の CSS のハッシュ）。すべての値を 1 つの関数 `h()` に通す。数は `data-k`（JSON のパス）で `--json` と照合でき、対応表と許可リストを明文で持つ
- **終了コード 1 を使わない**（ADR-0034 の H）: `aiqh history` は品質ゲートではない。過去に FAILED の run があっても 0

## 8. 学んだこと

- **生の文字の落とし穴**: v0.11.0 で、ツールの入力にエスケープを書くつもりが、テストのソースに生の U+202E が入り、自己 verify の 8 つのチェックを通って release に入った。見つけたのは、レビューのパケットを作るときの生の文字の確かめだった。v0.11.1 で、直した 2 か所を `String.fromCodePoint(…)` で組み立てる形にし、追跡しているすべてのファイルを確かめるテストを足した。verify の security の check が見つけないことは項目 48
- **diff の消した側の行**: パケットの生の文字の確かめは、差分の消した側の行も見る。範囲の始まりの時点からあった生の文字は、直した後でも、消した側の行に出て確かめに当たる（m4-history R1 のパケットは、そのファイルを `--exclude` で外し、依頼文に理由を書いた。`docs/reviews/m4-history/response-r1.md`）
- **期待値の変更が要るときの止まり方**: v0.11.2 の直しは、既存のテストの期待値（バグそのものを期待していた値）を変えないとできなかった。期待値の変更は承認の範囲の外なので、変える前に、直し方の案（数え方の違う 2 つ）と変わる期待値の場所を示した。人間が案 1 を選び、変えてよい 3 か所を承認してから直した（`docs/reviews/m4-history/response-r1.md` の「人間の決定」と「承認した期待値の変更」）
- **テストを先に書く順**: どの版も、新しいテストを先に書き、変更の前の commit の SHA 固定の worktree で FAIL を記録してから直した（v0.11.2: 10 件 FAIL、v0.12.0: 10 件 FAIL とモジュールの読み込みの FAIL、v0.12.1: 1 件 FAIL）。前も後も成り立つ守りのテストは PASS のまま残ることも記録した
- **作り直した commit の参照**: v0.12.0 で、照合の agent と見直しが、ADR-0034 の行の参照のずれ（コードの行が動いた）・CHANGELOG の古い commit の SHA・ADR-0035 の決定の番号の食い違いを見つけ、push の前に branch を作り直して検証を流し直した。v0.12.1 でも、運用テンプレートの照合で誤り 2 つを見つけ、push の前に commit を作り直した。commit を作り直したら、検証の前に、古い SHA と行の参照を探す

## 9. 確かめていないこと

- ブラウザごとの CSP の効き方（利用者が 1 つのブラウザで確かめた。ブラウザの種類と版は記録していない）
- Windows での `aiqh history` の挙動（対象外）
- CI の run の履歴の集計（再利用ワークフローは artifact を上げないので、`aiqh history` が読むのは手元の履歴だけ）
- 運用テンプレートの手順の実地（前の版に戻す・設定の変更の pull request を、実際の適用先ではまだ行っていない）
- FAILED の PR が必須チェックで止まる場面（M3 から引き続き、まだ起きていない）
- 32 MiB に近い大きさの実際の履歴（上限の境界はテストで確かめた。実際の履歴は 245,226 バイト）
