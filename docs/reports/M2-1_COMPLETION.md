## 1. M2-1 で作ったもの — `aiqh review-packet`

| 領域 | 内容 |
|---|---|
| パケットの生成 | `aiqh review-packet --range <from>..<to>`: commit 範囲から独立レビュー用の Markdown パケットを作る。両端は最初に完全 SHA に解決し、`<from>` が `<to>` の祖先でなければ exit 2 |
| 載せるもの | 人間が渡した依頼文（`--request`）と前回レビュー（`--review`）、commit メッセージ（trailer を除去）、変更ファイル一覧、ファイルごとの差分、`<to>` 時点の**全文**、`--doc` の文書、`<to>` の verify 結果（`latest.json` が `<to>` かつ clean のときのみ） |
| 載せないもの | **実装 AI の結論・自己評価・手書きの節**（Architecture Decisions / Verification Results の手書き表 / Known Risks）。作成者の名前・メールアドレス |
| fail closed の検査 | 不正な UTF-8・生文字（C0〈TAB・LF 以外〉・DEL・C1・U+2028 / U+2029・双方向制御文字・U+FEFF）・秘密の形を、オプションの値（git の前）→ すべてのパス → 入力ごと → 組み立て後、の順に検査し、1 件でもあれば何も書かない（exit 1）。値・行内容は出さず、出所・行・分類またはコードポイントだけ。`security.allow` は出所のパスと行に適用 |
| 描画の構造 | 描画する値は検査済みの型 `Checked` だけが描画関数と ZIP のエントリ名に渡り、本文は `md` タグ付きテンプレートで組み立てる。インラインコードの中に U+0060 を残さない（`\u{60}`）。オプションは `OPTION_INVENTORY` の 1 か所で扱いを決める |
| 書き込み | パケットと ZIP の 2 段階の書き込み（準備 → 確定）。確定点の前の失敗は戻し処理の各操作の結果を集めて報告、確定後の退避削除の失敗は警告（exit 0）。パケットと ZIP が同じファイルにならないことを、確定の直前にファイルシステムの同一性（親の `dev` + `ino`）で確かめる |
| ZIP | パケットだけを含む無圧縮 ZIP（Node 標準の `zlib.crc32`、固定 DOS 日時、新規依存なし）。`unzip` と Python の `zipfile` との互換性テスト |
| 再現性 | 本文に実行時刻を入れず、同じ範囲・入力・aiqh と git の版ならパケットと ZIP はバイト単位で一致 |
| 終了コード | 0 = 書いた、1 = finding があり書かない、2 = 使い方・git・上限・書込のエラー（検出が先） |
| 仕様・記録 | ADR-0014、README（信頼境界を含む）、ARCHITECTURE、CONFIG_SPEC、ROADMAP、`docs/reviews/m2-1/`（R1〜R4 の原文と対応記録） |

## 7. 学んだこと（M2-2 以降への持ち帰り）

- **列挙した経路だけ直すと別の経路が漏れる → 構造で固定する**: R2 の 4 件（ZIP のエントリ名、バッククォート、`--range` / `--doc`、finding の優先順位）は、R1 の修正で列挙した経路の外で起きた。
  検査済みの型と `md` テンプレートを入れた時点で、`latest.json` の値がそのまま埋め込まれる別の漏れが型エラーで見つかった
- **正規表現やテキスト解析の構造テストは迂回できる → AST や実体を使う**: `as Checked` の grep、help の解析、外部コマンドの正規表現は、どれも R3 で迂回の形を示された（R3-004〜006）
- **ファイルシステムの同一性は、文字列ではなくファイルシステムに問い合わせる**: realpath + NFC + `toLowerCase()` は APFS の名前の同一視と一致しない。親の `dev` + `ino` で比べる（R3-001）
- **重大度を下げる判断は、前提を実コードで確かめてから**: R3-001 は「同時の差し替えが必要」という前提で Medium に下げかけたが、確認の工程で差し替えなしの経路が見つかった。
  依頼書に停止条件（前提が崩れたら止まる）を書いておいたことで、完了扱いにする前に止まれた
- **検査は描画の前の値に、描画はバイト列の構造に合わせる**: エスケープした後の文字列を検査しても生文字は見つからない。CommonMark のコードスパンの中ではバックスラッシュはエスケープにならない
- **件数は数え方つきで書く**、**テストの期待値は Node の標準 API で計算する**（外部コマンドを使うなら有無を skip 条件に含める）

## 8. 運用の記録

- R3 の依頼は、最初の依頼で ChatGPT の安全フィルターに止められた。「防御用ツールのバグを探すレビューで、攻撃手法は求めていない」という前置きを足し、
  「再現手順」を「再現条件」とする表現に変えて再依頼した。R4 も同じ前置きで依頼した（どちらも人間による操作。レビューの観点は変えていない）
- 範囲の打ち間違い（R3 パケットの生成で `v0.41`）は exit 2 で何も書かれず、正しい範囲で再生成したことを報告に残した
- 各ラウンドとも、レビュアーの再現を実コードで再現してから判定し、回帰テストを先に書いて修正前 FAIL を記録し、commit ごとの worktree 検証を push の前に行った
