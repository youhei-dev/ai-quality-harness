## 項目 53: P3 の壁時計の上限（設計 §4）

**B2-Q7. P3 の 1 回の読みの上限を、どう確かめるか**【確定（2026-10-26）: A】【R2 で変更】
- R2 で変えた所: A を 53-F（CPU 時間の絶対の上限に、入力の大きさの比を足す）にし、比の上限を実測から決めた。受け入れの条件に「二乗の変異で落ちた記録」を入れた（B2-D-R1-003 への対応。設計 §4.6・§4.8）
- A（推奨・確定）: 53-F

  - 加えて、各形・各道具で 256 KiB と 1 MiB を 3 回ずつ読み、最小どうしが `t(1 MiB) ≤ 8 × t(256 KiB) + 20 ms` を満たすことを確かめる
  - 作業量の時計は残す。待つ時間の確かめは、テスト全体の上限（`it.each` の timeout）が受け持つ。4 MiB の確かめも CPU 時間にする
- B: 53-A（CPU 時間の絶対の上限だけ。R1 の A）
- C: 53-G（決定的な操作の回数。製品の `src/parse/` に仕事を数える引数を足す。v0.15.1 の範囲の外）
- D: 壁時計の上限を外し、作業量の時計と 40 秒の上限だけにする
- E: T3 の考え方で決め直す（静かな 1 回の読みの時間 × 12。約 1 秒になり、今より厳しい）
- F: 今のまま
- G: 同じ読みを 3 回行い、最も短いものを壁時計の上限と比べる（設計の 53-D。3 回とも待たされれば外れ、増え方は見ない）
- 推奨の理由
  - CPU を待つ時間が入らない。自分で終わる負荷のもとで、壁時計は 5.2 倍、CPU 時間は 1.5 倍になった【実測】

  - わざと二乗にした変異 2 つで、比が 8 つの形を落とした。そのうち 4〜5 の形は、1 MiB の CPU 時間が 584〜2,467 ms で、絶対の上限の内に収まり、比だけが見つけた【実測】。作業量の時計はどちらの変異にも気づかなかった
  - 製品のコードを変えない（v0.15.1 は src を変えない版）
- **最終（B2-D-R2-002 への対応）**: 受け入れの条件を 4 つにした（設計（最終）§4.8）。17 の形 × 5 つの道具の全部の組で測りが完走し 3 つの確かめを評価できたこと、打ち切りは検出の成功に数えないこと、40 秒を超えたら T3 の式で決め直すこと、二乗の変異は実際の P3 のテストを通して落ちた箇所を記録すること。v0.15.1 の実装レビューで確かめる
- 決めないと止まること: `tests/parse-output.test.ts:274`・`:282` の期待値の変更（B2-Q15）、時間の予算の 8-1 に足す決まりの文、実装の受け入れの条件（二乗の変異で落ちた記録）

## 項目 54: review-packet と出口の表記と層 (c)（設計 §5、ADR-0039 の案）

**B2-Q9. 層 (c) の文字を、パケットと出口でどう扱うか**【確定（2026-10-26）: A】【R2 で変更】
- R2 で変えた所: A に、判断の単位（元の文字列の上で、LF で分けた 1 行ずつ）と、表示の経路と保存の経路の書き分け（ファイルの JSON は値を変えない）を足した（B2-D-R1-002 への対応。設計 §5.6、ADR-0039 の案の決定 1・3・4）
- A（推奨・確定）: 54-A。v0.17.0（ADR-0039）
  - 禁止の集合（75。今のまま）に、層 (c) の文字のうち正しい絵文字の並び（RGI）の内側に無いものを加え、1 つの判断にする
  - 判断は**元の文字列の上**で行う。LF で分けた 1 行ずつを、行の終わりまで届いた 1 つの窓として渡す。security の check と同じ ADR-0037 の判断を使う
  - パケットは拒む。表示の経路（端末の行・端末の `--json`・`latest.md`）は値を表記（`\u{…}`）にする
  - 保存の経路（レポートと findings のファイルの JSON）は、**値を変えず**、値の上で決めた位置だけを `\uXXXX` で書く。U+FFFF より上はサロゲートの組。読み戻したデータは同じ
  - `FORBIDDEN_RANGES` は変えない
- B: パケットの側だけ（パケットの入力の確かめ・表示する値の確かめ・パスのオプション・review-import）。端末とファイルの出口は今のまま
- C: 出口の表記だけ。パケットは今のまま
- D: 受け入れて閉じる（ADR-0037 の既知の限界のまま、理由を書く）
- E: batch2 から外す（後の batch で決める）
- 選択肢に入れていない案
  - 設計の 54-F（`FORBIDDEN_RANGES` そのものに層 (c) を足し、RGI の並びも除かない）: 絵文字に付く U+FE0F・U+200D までパケットで拒まれ、出口で表記になる。適用先 A・B の追跡しているファイルの RGI の並び（除いた数 3・11【実測】）を含むパケットが作れなくなるので、退けた

- 推奨の理由
