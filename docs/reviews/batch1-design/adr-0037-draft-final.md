## 文脈

- ADR-0036（v0.13.0）で、security の check は層 (a)・(b) の 11 の符号位置（双方向の制御文字 U+202A–U+202E・U+2066–U+2069、行区切り U+2028・U+2029）を、中身とパス名で finding にした（既定で FAIL、分類を明示した allow だけが外す）
- ADR-0036 の既知の限界（`docs/adr/0036-security-scan-raw-bidi-controls-and-line-separators.md:80`）: 方向の印、ゼロ幅の文字、途中の U+FEFF、異体字セレクタ、タグ文字、11 の外の制御文字、同形異字は見ない（ROADMAP の項目 49）。見なかった理由は、正当な使い方があること（右から左の文書、絵文字の並びの U+200D、一部の文字の U+200C）と、Trojan Source の論文・Rust・clang-tidy が方向の印を対象にしていないこと
- 層 (c) の文字は、画面に見えないまま、識別子・文字列・文書の中身を変えられる。見えない文字の並びにデータや指示を隠す手口の報告もある [要確認]
- 実測（2026-10-21。追跡しているファイル。件数だけ）
  - aiqh 本体: 層 (c) の候補はすべて 0 件
  - 適用先 A: 異体字セレクタ U+FE0F が 3 件（3 ファイル）。すべて正しい絵文字の並びの中
  - 適用先 B: ゼロ幅 10 件（U+200D 9・U+200B 1。3 ファイル・4 行。意図した使い方）、異体字セレクタ U+FE0F 5 件（3 ファイル）。絵文字の並びの中は U+200D 6 と U+FE0F 5。外はゼロ幅 4 件（2 ファイル）
  - 方向の印・途中の U+FEFF・U+00AD・タグ文字・C0・C1・行の途中の CR・そのほかの既定で無視される文字（R1 の一覧）は、3 つとも 0 件
- 「正しい絵文字の並び」は、Unicode の RGI_Emoji（推奨の絵文字の並びの一覧）。Node の正規表現 `\p{RGI_Emoji}`（`v` フラグ）で判定できる（Node v24.13.1 で Unicode 17.0、実測）
- Unicode の属性との差分（Node v24.13.1・Unicode 17.0 で数えた）: `\p{Default_Ignorable_Code_Point}`（以下 DICP）は 4,174 の符号位置（うち割り当て済み 405）。R1 の案の集合には、DICP のうち U+180B–U+180D・U+180F・U+1BCA0–U+1BCA3（割り当て済み）と、U+2065・U+FFF0–U+FFF8・U+E0080–U+E00FF・U+E01F0–U+E0FFF（未割り当て）が無かった

## 決定

1. **見る文字**: 8 つの分類を足す（`src/security/raw-chars.ts` の `RAW_CHAR_CATEGORIES` と `SCANNED_RAW_RANGES`）。合計 4,247 の符号位置（層 (a)・(b) と重ならない）
   - `bidi-mark`（3）: U+200E・U+200F・U+061C
   - `zero-width`（4）: U+200B・U+200C・U+200D・U+2060
   - `bom`（1）: ファイルの先頭でない U+FEFF（1 行目の、行の中の位置 0 の BOM は今と同じく見ない）
   - `soft-hyphen`（1）: U+00AD
   - `variation-selector`（260）: U+180B–U+180D、U+180F、U+FE00–U+FE0F、U+E0100–U+E01EF（Unicode の Variation_Selector の属性と同じ集合）
   - `tag`（128）: U+E0000–U+E007F
   - `control`（63）: U+0000–U+0008、U+000B、U+000C、行の途中の U+000D、U+000E–U+001F、U+007F–U+009F（TAB・LF と、LF の前の CR・ファイルの最後の CR〈今も除いて読む〉は見ない。行の途中の CR は人間の決定 B1-Q15 による）
   - `invisible-other`（3,787）: そのほかの既定で無視される文字と、表示を持たない書式の制御の固定の一覧（U+034F、U+115F・U+1160、U+17B4・U+17B5、U+180E、U+2061–U+2065、U+206A–U+206F、U+3164、U+FFA0、U+FFF0–U+FFFB、U+13430–U+1343F、U+1BCA0–U+1BCA3、U+1D173–U+1D17A、U+E0080–U+E00FF、U+E01F0–U+E0FFF。未割り当ての DICP を含む）
   - **Unicode の属性との差分を固定する**（R2）: 次の差分をテストで固定する（ここでの「集合」は、8 分類と層 (a)・(b) の 11 を合わせた 4,258 の符号位置）。Node の Unicode の版が変わって差分が変われば、テストが FAIL して人が見直す
     - DICP − 集合: 無し
     - 集合 − DICP（意図して入れる。84）: `control` の 63、U+2028・U+2029（層 (b)）、U+FFF9–U+FFFB（行間の注釈の制御）、U+13430–U+1343F（聖刻文字の書式の制御）
     - 書式の文字（Cf）− 集合（意図して入れない。13）: U+0600–U+0605、U+06DD、U+070F、U+0890–U+0891、U+08E2、U+110BD、U+110CD（後ろの数字にかかる、表示のある印 [要確認]）
     - 制御文字（Cc）− 集合（意図して入れない）: U+0009（TAB）、U+000A（LF）
   - 層 (a)・(b) の 11 の符号位置と分類は変えない。`FORBIDDEN_RANGES`（75 の符号位置）も変えない（ADR-0020 の決定 3）
2. **出現ごとに finding**: ADR-0036 の決定 2 と同じ（同じファイル・行・符号位置は 1 件。パス名は同じパス・符号位置で 1 件）。決定 3 の除外は出現の位置ごとに判断し、この finding の鍵とは分ける（決定 3 の I9。R3）
3. **正しい絵文字の並びに完全に一致する区間の内側だけを除く**（R2 で不変条件にし、R3 で I5・I6 を書き直して I9 を足した）。次の I1〜I9 を不変条件とする
   - **I1 候補**: 除外を考えるのは U+200D・U+FE0F・U+E0020–U+E007F だけ。U+FE0E・U+E0001・U+E0100–U+E01EF・U+180B–U+180F は RGI の並びに現れない（下の集合 E の外）ので、常に finding
   - **I2 run**: 候補を含む、集合 E（`\p{Emoji}` と `\p{Emoji_Component}` の和）の文字が続く最も長い範囲を run とする。E の外の文字は、どの RGI の並びにも現れない（RGI の並びの文字はすべて E に入る [要確認: UTS #51 の定義]）
   - **I3 区切り**: run の先頭から、`\p{RGI_Emoji}` の最も長い一致を左から順に取る。run の外の文字はどの一致にも入らないので、この区切りは行の頭から区切ったものと同じ（run の途中から区切り始めない）
   - **I4 除外**: 候補が、ある一致の区間の内側にあるときだけ除く。一致と一致の間、run の端の候補は finding
   - **I5 窓の中での決め方**（R3）: 「窓の先頭」は行の始まりから届いていない窓の先頭、「保証された末尾」は行の終わりまで届いていない窓の最後の `lineOverlapBytes`（既定 4 KiB、最小 256。UTF-16 の単位）で、次の窓の先頭に必ず入る（`src/security/scan.ts:536-544`）。各窓で、候補を含む run ごとに次の順で当てる
     - (a) run の両端が見える（左右に E の外の文字、または行の始まり・行の終わり）→ I4 で決める
     - (b) (a) でなく、次のどれかなら、まだ決めていない候補を**その窓で finding に確定する**（除外しない）: その窓が行の最後の渡し（改行・ファイルの終わり）である / run が窓の先頭に接する（窓の先頭がサロゲートの組の後ろ半分だけのときも接するとみなす）/ run の左の隣の文字の始まりが、保証された末尾より前にある
     - (c) 残り（左の端が見え、右の端が窓の末尾に接し、左の隣から run の終わりまでが保証された末尾の中）→ その窓では決めない。次の窓の先頭に必ず入るので、次の窓でもう一度当てる
     - 決めずに次へ回せる長さは `lineOverlapBytes` で抑えられる。左の隣を含めてそれ以上の長さの run が窓の境目にまたがれば、必ず finding
   - **I6 1 回だけ決める・未決の候補を持ち越さない**（R3）: 候補の位置（行番号と行の中の位置）ごとに、ちょうど 1 回だけ決める。前の窓で決めた位置は、次の窓の重なりの中で決め直さない（保つ部分が重なりより長い窓でも同じ。除いた数を 2 回数えない）。未決の候補（位置・分類）を窓の外の状態として持たない（I5 の (c) の候補は、次の窓の先頭に入る文字の中にある）。行の最後の渡しでは (c) に当たらないので、決まらない候補は残らない
   - **I7 設定では変えられない**: 除外は Unicode のデータ（Node の正規表現の属性）だけで決まる。除いた数を出力に出す（`raw characters exempted (emoji sequences): N`）
   - **I8 Node の版**: `\p{RGI_Emoji}`・`\p{Emoji}`・`\p{Emoji_Component}` は同じ Node（ICU）の Unicode の版から来る。古い Node が新しい絵文字を知らなければ、その並びの候補は finding（FAIL の向き）
   - **I9 位置の判断と finding の鍵を分ける**（R3）: 走査する文字の出現（中身は行番号と行の中の位置、パス名はパス名の中の位置）ごとに「除く」か「finding の側」を 1 つ決める（「除く」は I1 の候補が I4 に当たるときだけ）。除いた数は「除く」の出現の位置の数。finding は決定 2 の鍵（中身は `src/security/scan.ts:410`・`:420-421`、パス名は `:430-435`）ごとに、「finding の側」の出現が 1 つでもあれば 1 件。「除く」の出現は finding を作らず、同じ鍵のほかの出現の finding を消さない。例: 同じ行に RGI の並びの中の U+200D が 2 つと並びの外の U+200D が 1 つ → 除いた数 2、finding 1。`security.allow` は finding だけに効き、除いた数を変えない
   - パス名は窓に分けないので、run の端はパス名の端か E の外の文字（`/` を含む）
4. **判定**: 既定で FAIL（`kind: "raw-char"` の finding → `aiqh security-scan` の exit 1 → check の FAIL）。入り切りのスイッチは作らない。警告の段も作らない
5. **範囲**: ADR-0036 の決定 4〜6 と同じ（同じファイルの集まり、`scanFile` の側だけ、パス名も見る、不正な UTF-8・UTF-16 は finding にしない）。走査は UTF-16 の単位から符号位置に変える（タグ文字と U+E0100 以上はサロゲートの組）。I5・I6 と行の途中の CR のために、行を窓で渡すときの位置、「行の終わりまで届いたか」、届いていない窓の保証された末尾の始まりを、生の文字の走査に渡す（秘密の形の走査は変えない）。範囲の細部は下の「対象範囲」
6. **allow**: 既存の `security.allow` の `category` に 8 つの分類を足す。生の文字の finding は、分類を明示した規則だけが抑える（ADR-0036 の決定 8 のまま）
7. **review-packet は変えない**（ADR-0036 の決定 9 のまま）
8. **出力とパーサ**: 件数の行の `raw characters: N` は層 (a)〜(c) の合計（パーサの数のキー `rawChars` の形は変えない）。`raw characters checked:` の行に分類を足す
9. **版**: 判定が厳しくなるので minor（v0.15.0 の案）。CHANGELOG の先頭に「判定が厳しくなる」と、規則の書き方の例（`category` を明示した規則）を書く

## 対象範囲（R2 で足した）

「層 (c) の全分類を既定で FAIL」は、security の check が中身を読むファイルの、UTF-8 として読めた文字と、パス名についての決定。次は見ない（ADR-0036 から引き継ぐものを含む）。

- 最初に読んだ塊の先頭 8 KiB（`BINARY_PROBE_BYTES`、`src/security/scan.ts:78`・`:589`）に NUL があるファイル: ファイルごとバイナリとして飛ばす。中の文字はどれも見ない。UTF-16・UTF-32 のファイルは、ふつう先頭に NUL があるのでここに入る。8 KiB より後の NUL は `control` の finding
- 不正な UTF-8 のバイト（finding にしない）
- TAB、LF、LF の前の CR、ファイルの最後の CR（`src/security/scan.ts:525`・`:555`）、ファイルの先頭の BOM
- 行の終わりまで届いていない窓の末尾の CR は、その窓では決めず、次の窓で決める（LF が続けば行の終わりの CR として除かれる）
- ルートのパス、symlink の先、submodule の中、ignore された未追跡のファイル
- review-packet（`FORBIDDEN_RANGES` だけを止める）
- 決定 3 の、RGI の並びに完全に一致する区間の内側の U+200D・U+FE0F・タグ文字（ただし、窓から消える位置で両端が確定しない run の候補は、並びの内側でも finding。I5 の (b)）

## fail closed との関係

- 判定を緩める道は、理由つき・期限つきで出力に残る明示の規則（`security.allow`）だけ（ADR-0012 と ADR-0036 の考え）。この ADR も、分類ごとに見るのをやめるスイッチと、FAIL にしない警告の段を作らない
- 除外（決定 3）は緩める道に見えるが、設定ではなく Unicode のデータで決まり、完全に一致した並びの区間の内側だけに効く。並びの外に続く見えない文字、並びとして正しくない組み合わせ、文脈が足りずに両端が確定しない run の候補は除かない（I4・I5）。窓から消える位置の候補はその窓で決め切り、未決のまま持ち越さないので、決まらずに落ちる候補は無い（I5・I6）。除いた数は出力に残る（位置の数。finding の数え方は変えない。I9）
- Node の版によって RGI_Emoji の中身が変わる。古い Node が新しい絵文字を知らないときは finding になり、FAIL の向き（安全側）
- 集合は DICP をすべて含み、DICP にない見えない文字も意図して入れた。差分はテストで固定し、Unicode の版の変化で黙って範囲が変わらないようにする

## 代替案

- **層 (c) の全分類を既定で FAIL、除外なし**（設計の C1）: 原則どおりだが、U+FE0F は絵文字にふつうに付き、実測で適用先の両方が FAIL する。利用者が広い規則で分類ごと抑えやすく、悪用の形まで抑える
- **層 (c) は数えて表示するだけ（警告の段）**（C2）: 今は「finding は FAIL」で、警告の段の finding は無い（`src/commands/security-scan.ts:57`・`:60`）。正当な使い方がほぼ無い分類（タグ文字、途中の U+FEFF）も門にならない
- **設定で入り切り**（C3）: ADR-0012 の `security.scanKeyValue`、ADR-0036 の `security.rawChars: false` を採らなかったのと同じ理由（fail open のスイッチ）
- **段階の導入（まず警告、後で FAIL）**（C5）: 振る舞いの変更が 2 回。実測が取れているので利点が小さい
- **候補の前後の決まった幅（例: 16 符号位置）だけを `\p{RGI_Emoji}` で調べる**（案 R1 の作り。R2 で退けた）: RGI の並びの最も長い長さを確かめないまま幅を決めることになり、部分の一致や片側だけの文脈で「並びの一部」と判定すると、外側の見えない文字を誤って除きうる（B1-D-R1-003）
- **窓をまたぐ未決の候補（位置と分類）を保持して、後で必ず決める**（R2 のレビューの修正案の 1 つ。R3 で退けた。人間の決定 2026-10-22）: 窓の外に状態が増える。`LineAssembler` が捨てた文字は戻らないので、保持しても、その run の左の端は後から確定できない。消える位置でその窓のうちに finding に確定すれば、状態を持たずに同じ FAIL の向きの結果になる（I5・I6）
- **Default_Ignorable_Code_Point を実行のたびに Node の `\p{Default_Ignorable_Code_Point}` で見る**: 集合が Node の版で黙って変わり、何を見るかを固定できない。一覧を固定で持ち、属性との差分をテストで固定する
- **方向の印を見ない**（ADR-0036 の代替案のまま）: 実測は 0 件で、allow で扱える。見ない理由（正当な使い方）は allow の理由として書ける

## 既知の限界

- 同形異字（CVE-2021-42694）は見ない（字の形の比べは別の仕組みが要る）
- 正しい絵文字の並びの中の U+200D などは見ない（決定 3）。並びそのものを悪用の形にする手口は扱わない
- 窓の境目にまたがり、左の隣を含めて重なり（`lineOverlapBytes`）以上の長さの run の中の候補と、窓の先頭に接する run の中の候補は、正しい並びの内側でも finding になる（I5 の (b)。FAIL の向きの誤り）
- U+FE0E（文字の表示の選択）と、モンゴル文字の異体字セレクタ U+180B–U+180F は、正当な使い方でも finding になる（allow で扱う）
- 漢字の異体字（IVS。漢字 + U+E0100–U+E01EF）も finding になる（allow で扱う。人間の決定 B1-Q16）
- 言語ごとの字句解析を持たないので、右から左に書く言語の文書の方向の印、組版のソフトハイフン、意図したゼロ幅の文字も finding になる（allow で扱う）
- UTF-16・UTF-32 のファイル、不正な UTF-8、ルートのパス、symlink の先、submodule の中は、ADR-0036 と同じく見ない（上の「対象範囲」）
- review-packet は `FORBIDDEN_RANGES` だけを止めるので、層 (c) の文字はパケットに入る（ROADMAP の新しい項目の候補）
