## 項目 49 の層 (c)（設計 §4、ADR-0037 の案 R2）

**B1-Q12. 層 (c) の方針**【R2 で変更】（R1-003 への対応）【R3 で変更】（R2-001・R2-003 への対応。推奨は C4' のまま）【確定】（C4'）
- 人間の決定（2026-10-21）: C4 を条件つきで採る。Unicode のデータで完全な RGI の絵文字の並びの両端を確定し、候補がその完全一致の区間の内側にあるときだけ除外する。窓の端などで文脈が足りないときは除外しない（FAIL 側に倒す）。これを ADR-0037 の不変条件にする
- C1: 全分類を既定で FAIL、分類つきの allow（除外なし）
- C2: 数えて表示するだけ（警告の段。FAIL にしない）
- C3: 設定で入り切り
- C4'（推奨。上の決定を、設計 §4.5 と ADR-0037 の案 R2 の決定 3 の不変条件 I1〜I8 にしたもの）: 全分類を既定で FAIL、分類つきの allow。候補（U+200D・U+FE0F・タグ文字）を含む run（Emoji・Emoji_Component の文字の続き）を、その先頭から `\p{RGI_Emoji}` の最長一致で区切り、候補が一致の区間の内側にあるときだけ除く。run の両端が窓の端で確定しないとき（重なりより長い run）は除かない。候補の位置ごとに 1 回だけ決める。除いた数を出す
  - **R3（R2-001）**: 窓から消える位置にある候補で run の両端が確定しないものは、その窓で finding に確定する。決めずに次の窓へ回すのは、次の窓の先頭に必ず入る末尾（`lineOverlapBytes`）の中の run だけで、未決の候補を窓の外に持ち越さない（I5・I6）
  - **R3（R2-003）**: 位置の判断（除く・finding の側）と finding の鍵を分ける。除いた数は位置の数。finding は今のまま「ファイル・行番号・符号位置」で 1 件（パス名は「パス・符号位置」で 1 件）（I9）
- C5: 段階（まず C2、後で C4'）
- 理由: fail closed（ADR-0012・ADR-0036: 緩める道は明示の規則だけ、スイッチを作らない）を保ったまま、実測で適用先 A は 0 件、適用先 B は 4 件・2 ファイル（規則 2 つ）に収まる。R1 の「候補の前後の決まった幅」は、部分の一致や片側だけの文脈で外側の見えない文字を誤って除きうるので、run の先頭から区切る形にした（行の頭から区切るのと同じ結果になる）

**B1-Q13. 絵文字の並びの除外に使う Unicode のデータ**【R2 で変更】（理由の文だけ。推奨は R1 のまま）【確定】（A）
- A（推奨）: Node の正規表現 `\p{RGI_Emoji}`、`\p{Emoji}`、`\p{Emoji_Component}`（Node の版で中身が変わる）
- B: aiqh の中に、固定の版の一覧を持つ
- 理由: 依存を増やさず、一覧の保守も要らない。3 つの属性は同じ Node（ICU）の Unicode の版から来るので、run の区切り（E の集合）と RGI の一致が食い違わない。古い Node が新しい絵文字を知らないときは finding になる（FAIL の向き、安全側）

**B1-Q14. 方向の印（U+200E・U+200F・U+061C）を FAIL の対象に入れるか**【確定】（A）
- A（推奨）: 入れる（分類 `bidi-mark`）
- B: 入れない（今と同じく見ない）
- 理由: 実測は 3 つのリポジトリで 0 件。右から左の文書で使うプロジェクトは、理由つきの規則で外せる。Trojan Source の論文・Rust・clang-tidy が対象外にしている点は、ADR-0037 の代替案に記録する

**B1-Q15. `control` の範囲**【R2 で変更】（推奨は R1 のまま。境界と窓の扱いを足した）【確定】（A）
- A（推奨）: TAB・LF と、LF の前の CR・ファイルの最後の CR を除く C0・DEL・C1 すべて（U+000C・U+001B・行の途中の CR を含む。63 の符号位置）
  - 境界（R1-006 への対応。設計 §4.8 の L21・L22 で固定）: 先頭 8 KiB に NUL があるファイルはバイナリとして飛ばす（中を見ない）。8 KiB より後の NUL は finding。行の終わりまで届いていない窓の末尾の CR は、その窓では決めず、次の窓で決める
- B: U+000C（改ページ）と U+001B（ESC）を除く
- C: A から行の途中の CR だけを除く
- 理由: 実測は 3 つのリポジトリで 0 件（行の途中の CR も 0）。改ページ・ESC・行の途中の CR は端末の表示を変えられる。使うプロジェクトは規則で外せる。窓の末尾の CR を先に決めると、CR LF が窓の境目にまたがったときに誤って finding になるので、次の窓に回す

**B1-Q16. 漢字の異体字（IVS。漢字 + U+E0100–U+E01EF）の扱い**【確定】（A）
- A（推奨）: 除外しない（finding。allow で扱う）
