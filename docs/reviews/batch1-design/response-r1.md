### B1-D-R1-001 — node:test の検出の証拠（受け入れ）

- **指摘の要点**: 「同じ単純コマンド内に `node` と `--test`」がプログラムの位置を確かめないなら、`echo node --test`、`node -e "console.log('--test')"`、`node script.js --test` なども available になりうる。`node script.js --test` は Node 自体のテストのモードとも限らない。N5 はこれらを含まない
- **対応**（設計 R2 の §2.4「45-A の規則」、付録 A）
  - 付録 A の語の分け方（引用符を解き、引用ありの語に印を付ける）で単純コマンドに分け、環境変数の前置きを飛ばした最初の語（実行位置）が、印の無い `node` そのもののときだけ見る
  - Node のオプションを左から読み、`--`・スクリプトの名前・本文を取るオプション（`-e`・`--eval`・`-p`・`--print`）で読むのをやめる。値を別の語で取るオプションは固定の一覧で値を飛ばし、一覧に無いものの値はスクリプトの名前と見なす（その後ろの `--test` は認めない）
  - 読んだオプションに印の無い `--test` があれば認める。`--watch`・`--watch-path` があれば認めない（verify の check が終わらないので。R2 で足した細部）
  - パスつきの `node`、`npx`・`env`・`cross-env` を挟んだ形は認めない（検出しないだけ。§2.8 の既知の限界）
  - ADR-0011 の追記の文も、この規則に合わせた（§2.7）
- **テストの計画**（設計 R2 の §2.6）: N2b（値を取るオプションの後の `--test`）・N6b（環境変数の前置き）を認める側に、N5a（`echo`）・N5b（`-e`・`--eval=`）・N5c（スクリプトの引数）・N5d（引用ありの `--test`）・N5e（`--` の後）・N5f（`printf`）・N5g（パスつき・`npx`・`env`・`cross-env`）・N5h（一覧に無い値つきのオプション）・N5i（`--watch`）・N5j（閉じていない引用符）・N5k（コマンドの置き換え）・N6c（2 つめの単純コマンドの `echo`）を認めない側に足した。守りの行は `NODE_ADAPTERS` を全部回す書き方で、基準の commit でも PASS する

### B1-D-R1-003 — RGI_Emoji の除外の不変条件（受け入れ。C4 を条件つきで）

- **指摘の要点**: C4 は候補の前後 16 符号位置という例に頼り、RGI_Emoji の最長の長さ・境界の正しさを確かめないまま固定する。部分の一致や行の窓の片側だけの文脈で「一致した絵文字の一部」と判定すると、外側の見えない文字を誤って除きうる
- **対応**（設計 R2 の §4.5・§4.7、ADR-0037 の案 R2 の決定 3）
  - 不変条件 I1〜I8 を置いた: 候補は U+200D・U+FE0F・U+E0020–U+E007F だけ（U+FE0E・U+E0001・U+E0100 以上・U+180B–U+180F は RGI の並びに現れないので常に finding）。候補を含む run（`\p{Emoji}` と `\p{Emoji_Component}` の文字の続き）を、その先頭から `\p{RGI_Emoji}` の最長一致で区切る。E の外の文字はどの並びにも入らないので、行の頭から区切ったのと同じ結果になる。候補が一致の区間の内側にあるときだけ除く
  - 文脈が足りないとき（run の端が、行の始まりから届いていない窓の先頭、または行の終わりまで届いていない窓の末尾に接する）は、その窓では決めない。次の窓は少なくとも `lineOverlapBytes` を持ち越すので、短い run は次の窓で決まる。どの窓でも両端が見えない run の候補は除かない（FAIL の向き）。位置ごとに 1 回だけ決める
  - そのために、`LineAssembler` が窓を渡すときに、窓の先頭の行の中の位置と、行の終わりまで届いたかを、生の文字の走査に渡す（秘密の形の走査は変えない。§4.7）
  - R1 の「候補の前後の決まった幅」は、ADR の代替案に「退けた」として残した
  - Node v24.13.1 で、見本の RGI の並び 7 つ（ZWJ の家族・異体字セレクタつき・タグの旗・キーキャップ・肌の色・虹の旗・国旗）がすべて一致し、その文字がすべて E に入ることを確かめた。RGI に無いタグの旗・文字の表示の選択・数字だけは一致しないことも確かめた
- **テストの計画**（設計 R2 の §4.8）: L13（タグ列: RGI の旗・RGI に無いタグの並び・基の無いタグ・旗の後ろの余分なタグ）、L14（隣接した余分な U+200D・二重の U+200D・二重の U+FE0F・絵文字の直後の U+200B・U+FE0E）、L15（連続した絵文字）、L16（長い行: 既定の窓の境目、小さい窓で重なりより長い run、窓の大きさを変えても結果が同じ）、L17（パス名: `/` をまたぐ形を含む）、L18（E の外の候補）、L19（I2 の前提の確かめ）

### B1-D-R1-005 — 型ガードのテストの時間の予算（受け入れ）

- **指摘の要点**: 推奨の 8 倍は観測した倍率（最大 10.3 倍）より小さい。300 秒の上限は unit の 600 秒の半分を占めうる。「CI の実行時間が変わらない」という説明は、止まらない遅さのときには成り立たない。負荷のゲート・並列数・各テストと suite の時間の予算を別々に定義し、観測した倍率を覆う根拠のある上限と、閾値に近い遅さの記録を
- **対応**（設計 R2 の §5.3・§5.5）
  - SP1 の記録（vitest の JSON。ミリ秒）から倍率を出し直した: 2.33〜10.33 倍（最大は 2.76 秒 → 28.5 秒のテスト）。静かなときに短いテストほど倍率が大きい。R1 の「14 ファイル」は数え直すと 15 ファイルだったので直した
  - 時間の予算を 4 つに分けて定義した: T1 負荷のゲート（手元。文書にする）、T2 並列数（同時に 1 本。vitest の worker は CPU − 1 のまま）、T3 各テストの上限（負荷で伸びるテストは max(30 秒, 静かなとき × 12)。12 は 10.33 に約 16% の余裕。200 秒〈T4 の 1/3〉を超えるものは分ける）、T4 suite の予算（unit・unit-minpath の 600 秒。CI で 50% を超えたら記録して ROADMAP の項目を早める）
  - T3 を当てた上限の表を置いた（13 件を 40〜160 秒に。builtin-r3 の「every edit」は式で 400 秒になるので、編集ごとの 19 の `it` に分ける）。上限を広げてもガードの検出の力は変わらず、止まったテストを見つけるまでの時間が延びるだけで、それも T4 で抑えられることを書いた
  - 上限に近い遅さの記録を B1-Q25 にした（推奨: vitest の reporter が上限の 50% を超えたテストを run の終わりに stderr に出す。`latest.json` の `stderrTail` に残る。判定は変えない）
  - 並列の抑制と program の再利用は、ROADMAP の新しい項目の文案にした（付録 B の 1・2）
- **テストの計画**（設計 R2 の §5.7）: T3 の上限にした後、L2 と同じ負荷で全テスト 2 本が時間切れにならないことと、各テストの時間の記録。分けた「every edit」が同じ 19 の編集を同じ期待で確かめること。reporter の判定の関数の単体のテスト

### B1-D-R1-006 — Unicode の属性との照らしと境界のテスト（受け入れ）

- **指摘の要点**: review-packet 用の禁止の集合は別に持っている。新しい分類は Default_Ignorable_Code_Point の「主なもの」で網羅の集合ではない。U+0000 は先頭 8 KiB のバイナリの判定で走査されず、「全分類 FAIL」には対象範囲の注記が要る
- **対応**（設計 R2 の §4.4・§4.7・§4.10、ADR-0037 の案 R2 の決定 1・対象範囲）
  - Node v24.13.1（Unicode 17.0）の属性で差分を出して表にした: DICP にあって R1 の集合に無かったのは U+180B–U+180D・U+180F・U+1BCA0–U+1BCA3（割り当て済み）と U+2065・U+FFF0–U+FFF8・U+E0080–U+E00FF・U+E01F0–U+E0FFF（未割り当て）。集合にあって DICP に無いのは制御文字・U+2028・U+2029・U+FFF9–U+FFFB。Cf で集合に無いのは前に置く印と聖刻文字の書式の制御
  - 推奨（B1-Q17 の A'）: DICP の全部を入れ、U+13430–U+1343F も入れる。前に置く印 13 と TAB・LF だけを意図して対象外にする。これで `variation-selector` は Variation_Selector の属性と同じ 260、8 分類の合計は 4,247
  - 差分の 5 行をテスト L20 で固定する（Node の Unicode の版が変われば FAIL して人が見直す）
  - 対象範囲の注記を、設計 §4.10 と ADR-0037 の案 R2 の新しい節「対象範囲」に書いた（先頭 8 KiB に NUL があるファイルは中を見ない、不正な UTF-8、TAB・LF・行末の CR・先頭の BOM、ルートのパス・symlink の先・submodule の中、review-packet、RGI の並びの内側）
  - 窓の末尾の CR は次の窓で決める（CR LF が窓の境目にまたがったときの誤った finding を避ける。§4.7）。先頭の BOM は窓の位置ではなく行の中の位置で決める
  - review-packet の禁止の集合を変えないことは、ADR-0036 の決定 9 のまま。既知の限界として書き、ROADMAP の項目の候補にした（付録 B の 5）
- **テストの計画**（設計 R2 の §4.8）: L20（差分の 5 行）、L21（8,191 バイト目と 8,192 バイト目の NUL）、L22（行の途中の CR・CR LF・ファイルの最後の CR・CR CR LF・窓の境目の CR LF）、L23（先頭の BOM・二重の BOM・2 つめの窓の先頭の BOM）
