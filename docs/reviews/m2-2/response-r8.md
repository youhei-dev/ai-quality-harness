## レビュアーの「未確認の範囲」の扱い（新しい作業は起こさない）

レビュアーは、パケットの外（今回のパケットに全文が無いもの）を断定しなかった。人間の判断で、次のとおり記録する。

1. **`src/cli.ts` の、すべての throw の箇所から、調べると例外になる値が届かないか**
   - 既知の限界として、ROADMAP のバックログ 1（CLI の最上位の catch）で扱う
   - 追記（v0.5.14）: CLI の最上位の catch は v0.5.14 で直した。`src/` のすべての throw の箇所の棚卸しは、`docs/reviews/m2-2/response-r7.md` の v0.5.14 の節
2. **42 通りのバイト比較の中身**
   - この比較は、リポジトリのテストではない。git 管理外の道具（`tmp/m2-2/r4-001/bytes/compare.ts`。v0.5.4 のバイト比較の道具の写し）で、各版の停止ポイントで流している
     （レビュアーは「既存の byte-for-byte の回帰テスト」を前提にしたが、テストとしては無い）
   - v0.5.12 では、SP2 で人間の承認のもと実測した（SP2 報告 §5）
     - 基準は、同じ時間帯の v0.5.11 の一時 worktree（commit 3 と HEAD には、版だけを 0.5.12 に合わせた基準）
     - 比べたのは各 commit と HEAD。42 通り（通常 40、利用者由来の TAB 2）すべてがバイト単位で一致した
     - 基準の取り直しでも一致した
   - リポジトリのテストとしては、R4-001 の回帰テストの対照（JSON のデータの出力が v0.5.9 の式と同じこと）と、R7 の回帰テストの対照（普通の Proxy・転送だけの
     Proxy の出力が普通の値と同じこと）がある
3. **変更していないコマンドの `--json` の値が、すべて JSON のデータか**
   - 既存の回帰テストと ADR-0018 の範囲で扱い、今回は追加の作業をしない
   - 参考（これまでの記録）: v0.5.10 の SP1 で、vitest とバイト比較の中のコマンドからの `safeJson()` の呼び出し 35 回に JSON のデータでない値は 0 件だった。v0.5.11 で、利用者の入力の入り口（jsonc-parser・zod・`JSON.parse`・git の出力・ファイル名）が Proxy・accessor・普通でないプロトタイプをコマンドの値に届けないことを確かめた
4. **既知の範囲外**（レビュアーは依頼の指定どおり指摘にしていない）
   - CLI の最上位の catch の修正そのもの、ファイルへの出力の JSON（`maskDeep()`）、同じプロセスの中のプロトタイプの汚染、Proxy を Proxy として検出しない設計、M2-2-R4-002 などのバックログ、Windows、所要時間
