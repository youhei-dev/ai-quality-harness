## (2) v0.18.2: C-44（`:170-175` の既知の限界の書き換え）

今の `:170`・`:174`:
- 「実際のレンダラ（GitHub・エディタのプレビューなど）での表示は見ていない。仕様の規則から判断した」
- 「コマンドと作業ディレクトリは 1 つのバッククォートの code span の中にあるので、バッククォートを含む値はそこで閉じうる」

`:174` を残し（書いた時点の記録）、その下に注記:

- 注記（v0.18.2）: `latest.md` のコマンド（Checks の表の Command の列と、失敗の詳細の `- Command:`）と作業ディレクトリ（`cwd:`）は、Summary の行と同じ `codeSpan()` で包む（中の最も長いバッククォートの連なりより 1 つ長い区切り。値がバッククォートで始まるか終わるとき、または空白で始まり空白で終わる〈空白だけではない〉ときは、両端に空白を 1 つずつ足す。CommonMark 0.31.2 §6.1）。今までと同じバイト列になるのは、バッククォートを含まず、空白で始まり空白で終わる形でない値（B4-D-Q5）。これを golden fixture の `plain` の組で固めている（ADR-0003 の追記〈v0.18.1〉）。表のセルの中では、今までどおり `|` を `\|` にしてから包む（GFM の表のセルの規則）。テストは、バッククォートと区切り（`|`）・端の空白・連なりの組み合わせ（先頭がバッククォートで末尾が空白、`|` の直前・直後のバッククォート、3 つの連なりと `|`、両端の空白と `|`）を持つ
- **既知の限界（v0.18.2）**: 表の外の `- Command:` の行でも、`|` は `cell()` で `\|` にしたまま包む（B4-D-Q6）。表の外の code span の中では、バックスラッシュのエスケープが効かないので、**`\|` のバックスラッシュが字のまま見える**見込み（例: `npm test \| tee log` と見える）。直すと、バッククォートを含まない値（`|` を含む値）の出力が変わるので、今回は直さない。描画は、今も仕様からの判断で、実際のレンダラでは確かめていない
