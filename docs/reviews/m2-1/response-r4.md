## M2-1-R3-001 の判定（レビュアー）

- **解消**。準備段階で親ディレクトリを作った後、実際に解決された親へ一時ファイルを書き、その親の `dev` + `ino` を保存し、既存ファイルを退避する前の
  `check:same-target` で、(1) 各パスから今見える親が準備時と同じ `dev` + `ino` か、(2) packet と ZIP の親が同じ実体で ASCII の basename が大文字小文字を無視して同じか、を確かめる。
  APFS 等が同一視する親名を NFC + `toLowerCase()` が同一視できない経路は、文字列ではなく親ディレクトリの実体で拒否される
- `check:same-target` の後に他者が出力先の親を差し替える競合の窓は残るが、依頼で明示した信頼境界の外であり、未解消扱いにしない

## レビュアーが確認した点（指摘ではない、5 項目の要約）

1. **packet と ZIP が同じファイルへ書かれる経路**: 文字列の比較は早期の拒否として残り、最終判定はファイルシステムの同一性。同じ親の case-only の別名も拒否される。
   **最終要素がシンボリックリンク**・ディレクトリ・その他の非通常ファイルなら、`lstat` と `isFile()` で準備段階に拒否される。**通常ファイルへのハードリンク**（異なる basename の
   2 つのパスが同じ inode）は、rename が inode ではなく個々のディレクトリエントリを置き換えるため、書き込み後は packet と ZIP の別 inode になり、1 つに潰れる経路にはならない
   （レビュアーが POSIX の最小のファイル操作で確認）。basename は ASCII に限られるため、basename 側で同種の Unicode 同一視の漏れが残る構造は無い。Windows は対象外
2. **判定したディレクトリと書き込むディレクトリ、一時ファイル・退避・後片付け**: 一時ファイルは実ディレクトリの中に作られ、準備中に親のシンボリックリンクが変われば確定前に拒否される。
   拒否は準備段階の `try` の中で起き、`removeTmps()` で一時ファイルが消され、既存ファイルには触れない。確認の後の外部の差し替えは信頼境界の外
3. **安全側の拒否が通常利用を妨げていないか**: 早期の文字列比較による拒否は依頼の「安全側に拒否する」仕様どおり。親の `dev` + `ino` が異なり basename も衝突しない通常の 2 出力は拒否しない。
   準備後に親が変わった場合の exit 2 も fail closed として妥当
4. **回帰テストが修正前に FAIL し、環境依存で誤 PASS / 自爆しないか**: 名前の組は、テスト自身がファイルシステムの扱いを確かめて期待値を切り替えるため、APFS と Linux の違いに固定の仮定を置かない。
   差し替え 2 件と衝突のない親の変更 1 件は、v0.4.2 のコードでは期待する exit 2 にならず、名前の組がすべて区別されるファイルシステムでも「旧コードで全テストが誤って PASS」にはならない。
   後始末は `afterEach` で行い、例外を握りつぶさない。特殊な文字は `String.fromCodePoint()` で実行時に作る
5. **docs の一致、R3-002〜006 の持ち越し、ADR の訂正**: README の信頼境界、ADR-0014 の同じ実体の判定・R3-002 / 003 の未解決の状態・R3-004 / 005 の保証の限界、ROADMAP の M2-2 の先頭の 5 件、
   response-r3 と CHANGELOG が、実コードの現状と一致
