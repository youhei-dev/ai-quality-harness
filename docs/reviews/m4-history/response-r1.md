## 指摘ごとの対応

### M4-H-R1-001 — 出力の上限が、実際に標準出力に書く全部のバイトに当たっていない（受け入れ）

- **指摘の要点**: 出力の 32 MiB の上限を、表は最後の `HISTORY COMPLETE` / `HISTORY INCOMPLETE` の行を数えずに、`--json` は書くときに足される改行を数えずに判定している。境界のテストも、実際に書いたバイト数で確かめていない
- **コードで確かめたこと**（`074ebc4`）[事実]
  - 表（`src/commands/history.ts:105-109`）: 表の各行と改行の合計だけを上限と比べ、そのあとで最後の行を `output.log` で足していた
  - `--json`（`src/output.ts:233-238` の `jsonWithin`）: `safeJson` の文書の UTF-8 のバイト数だけを比べていた。既定の書き手は `console.log` で、改行の 1 バイトを足す
  - テスト: `tests/history-cli.test.ts` の表の境界は `full.out.slice(0, -1)` で最後の行を除いて上限を作り、`--json` の境界は書き手が受け取る改行の前の文字列で上限を作っていた
  - 数（テストの fixture `project(2)`）: 表は、比べていた数が 954 バイト、実際に書く数が 1,005 バイト（最後の行 50 バイトと改行）。`--json` は 3,621 バイトと 3,622 バイト
- **対応**（v0.11.2、commit `69f05bb`）
  - `src/output.ts`: 上限つきの口は、標準出力に実際に書くバイト（各行または文書と、その後ろの改行）を先に数え、書き手の種類によらない同じ数で判定する。上限以下のときだけすべてを書き、超えたら何も書かない。`jsonWithin` は改行を数える。新しい口 `linesWithin(lines, maxBytes)`（各行は `log` と同じ処理）。新しい書き手 `write`（標準出力のバイトをそのまま受け取るテストの書き手。上限つきの口が書くものは 1 つの文字列を 1 回で受け取る。`log` の代わり）
  - `src/commands/history.ts`: 表のすべての行と最後の行を `linesWithin` に渡す。`HistoryOptions.write`
  - 既定の書き手は、上限を確かめた後に 1 行ずつ `console.log` で書く（書くバイトは数えたものと同じ）。行ごとに処理した文字列を 1 つにまとめて処理し直さないのは、マスクに行をまたぐ規則（PEM の鍵の区間、`bearer` の後ろの空白など）があり、まとめると中身が変わりうるため。`Safe` を作るのは `safeText`・`safeJson` だけのまま（`tests/structure/output-guard.ts` は変えていない）
  - 変えていないもの: 上限の値（32 MiB）、終了コード、`HISTORY ERROR (<種類>)` の種類、上限の中の出力のバイト（v0.11.1 と同じ。CLI の標準出力と `write` が受け取るバイトを比べるテスト）
  - 決まりの記録: ADR-0034 の H（「上限は、標準出力に実際に書くバイト〈各行と改行、文書と改行〉に当て、書き手の種類によらない」と、v0.12.0 の HTML のファイルにも同じ決まり〈実際に書くファイルのバイト〉を当てること）・I・M・N、ADR-0016 の注記
- **テスト**
  - `tests/history-output-bytes.test.ts`（新規、7 件）: 書き手 `write` が受け取ったバイト数で、表と `--json` のそれぞれに、上限ちょうど（書く）・1 バイト超過（何も書かない、exit 2）・最後の行（表）や最後の改行（`--json`）だけで超える（何も書かない、exit 2）。`HISTORY INCOMPLETE` の最後の行も数える。書き手 `log` でも同じ上限で同じ答え。`write` が CLI の標準出力と同じバイトを受け取る。`--json` では、文書の後ろの 1 バイトは改行だけなので、「1 バイト超過」と「最後の改行だけで超える」は同じ上限（文書のバイト数）になる
  - 6 つの境界の数（同じ fixture。名前に多バイトの文字）: 表は出力 1,012 バイトで、上限 1,012 は書く（exit 0）、1,011 と 961（最後の行の 51 バイトを除いた数）は何も書かない（exit 2）。`--json` は出力 3,629 バイトで、上限 3,629 は書く、3,628 は何も書かない
  - テストを先に書き、変更の前の `074ebc4` の SHA 固定の worktree に、新しいテストと期待値を変えた 2 つのファイルを写して走らせた: 10 件 FAIL（新しい 7 件と変えた 3 件）、13 件 PASS（変えていない既存のテスト）。直した後は 23 件 PASS、全テストは 171 ファイル・2,285 件 PASS
- **承認した期待値の変更**（人間の承認、2026-10-18。この 3 か所だけ）
  - `tests/history-cli.test.ts` の「the table」: 表から最後の行を除いた上限で、全部が出る → 何も出ない（`output-too-large`、exit 2）。このテストは「最後の行だけで超える」場合のテストになった
  - `tests/history-cli.test.ts` の「--json」: 境界を、文書と改行のバイト数にした（上限ちょうどで書く、1 バイト少ない〈文書だけ〉と `output-too-large`）
  - `tests/output-json-within.test.ts` の境界: 同じく、文書と改行のバイト数にした
  - 3 つのテストの名前と、2 つのファイルの冒頭の説明の文を、新しい決まりに合わせた
- **既知の限界**: 既定の書き手は 1 行ずつ書くので、書いている途中で標準出力が閉じたとき（パイプの相手が終わったときなど）は、一部だけが書かれうる（v0.11.1 までと同じ）。標準エラー（`--json` のときの最後の行、誤りの行）は上限に数えない（固定の文と数だけ）

## 問いへの答えの要約（レビュアー）

1. 出力の上限に指摘あり（M4-H-R1-001）。マスクの単位、数の葉の上限、run ごとの割合、安全な整数と有限には指摘なし
2. 設計 R1 の対象 4 件に指摘なし
3. 記述子の確かめ、上限、分類、読まない欄の捨て方、`counts` の既知のキーだけの Map への写しに指摘なし
4. 保持する対象を限った集計と出力、マスクの後の切り詰めに指摘なし
5. 出力の上限の判定に指摘あり（M4-H-R1-001）。終了コードの振り分け、読めない情報、決定的な並びに指摘なし
6. 1 つの Buffer からの設定の文字列と SHA-256、`timeoutSec` の上限と設定の誤りの扱いに指摘なし
7. 最後の行と改行を含む実際の出力のバイト数の境界テストが足りない（M4-H-R1-001）。ほかの境界・競合・目印の文字列のテストに指摘なし
8. 追跡しているすべてのファイルの禁止文字の確かめと、出力の制限に指摘なし。ROADMAP の項目 48（対象のプロジェクトの security の check の見逃し）を Medium として後の版に回す記録は、優先順位として妥当。ただし継続して管理が要る
