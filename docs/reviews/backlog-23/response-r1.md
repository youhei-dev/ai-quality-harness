## 問いへの答え（レビュアーの結論の要約。実装者の評価ではない）

1. **内外の判定**: 問題なし。`realpathSync(root)` と `realpathSync(file)` の最終の実体同士を `path.relative()` で比べるので、根自体が symlink、`..foo`、リンクの連鎖（中 → 外、外 → 中）、外を指す相対リンク、`proj` と `proj2` の取り違えのどれでも、外を中と誤る経路は見つからなかった
2. **大文字と小文字を区別しないファイルシステム**: 外を中と誤認する実装上の経路は見つからない。実機での表記の違いは未確認（B23-R1-001 に含めた）。誤るとしても、中のリンクを外とみなす拒否の向き
3. **拒否の位置と順序**: 妥当。既に行がある `.gitignore` でも exit 2 になる点は、少し保守的だが「root の外のリンク先を書込先として扱わない」契約として一貫している
4. **既存の使い方を壊す範囲**: README・CONFIG_SPEC §5.3c・CHANGELOG と案内の文言で、十分に文書化されている（「monorepo」の語は無いが、「project root の外」で契約は明確）
5. **出力の境界**: 問題なし。リンク先の絶対パスは既存の出口（`createOutput()`）を通る、利用者自身の端末への診断で、外へ送るコードは無い
6. **N1 の dangling の拒否**: 開始時から dangling の `package.json` は O6 が先に止めるので、ほぼ冗長。害は無く、監査の後に差し替えられた場合の遅い検査として意味がある
7. **テスト**: 主要な契約と互換性の変更は固定している。境界の回帰テストが少し足りない（B23-R1-001）

依頼文で既知の限界として除いた項目（TOCTOU・ハードリンク・Windows）は、再指摘していない。
