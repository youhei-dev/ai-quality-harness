## 全体の結論

件数: High 0 / Medium 0 / Low 0

本パケットの範囲で、新たに報告すべき High・Medium・Low の指摘は確認できなかった。R1 の 3 件はいずれも解消と評価する。したがって、依頼文の終了基準である High・Medium 0 件を満たす。ただしこれは添付ソースに対する静的レビュー結果であり、あらゆるレンダラや同時書き込み環境での完全性を実証するものではない。

**問い 1 — R1 の 3 件:**

- M2-2-RI-R1-001: 解消。`src/review/import.ts` の `refusedReferences` が許可された五つ以外のセミコロン付き名前参照を検出し、legacy の危険な十名称も拒否する。数値参照は `fold` で復元し、`htmlForms` が元の文字列に加えて HTML を取り除いた二つの表現を照合する。本文の行だけでなく JSON 解析後の各文字列も検査する。関連する回帰テストは検出例・正常例の両方を含む。
- M2-2-RI-R1-002: 解消。`src/report/write.ts` で暗号学的乱数から一時名を作り、排他的作成と `O_NOFOLLOW` 付きの再オープンにより、前回の予測可能な一時名を使ったシンボリックリンク追跡経路を塞いでいる。失敗時の一時ファイル削除も維持する。
- M2-2-RI-R1-003: 解消。`src/commands/review-import.ts` の既存ファイル分岐は、ハッシュ一致だけで成功せず、保存済み label・round・idPrefix を検査し、通常取込と共通の `checkPrevious` を呼んだ後に exit 0 に進む。前回ファイルの不存在・破損・不一致を調べる回帰テストを確認した。

**問い 2 — ID 検出と fail open:** 名前参照の拒否、数値参照の復元、HTML コメント・タグを取り除く照合を確認した。依頼の範囲で新たな fail open の具体的経路は特定できなかった。Markdown と HTML のあらゆる表示解釈を再現しない制約は ADR-0026 に明記されており、今回の再指摘対象から除外した。

**問い 3 — writeAtomic:** ランダム名・排他的作成・再オープン時の非追跡・rename・失敗時削除を確認した。通常の単独実行において前回指摘のリンク追跡と外部ファイル上書きが残る経路は確認できなかった。`writeReports` は引き続き `writeAtomic` を利用し、履歴名予約後の失敗時処理も維持されている。同時に一時ファイルを差し替える攻撃と強制終了による残骸は依頼に明示された既知の限界として扱う。書き込み失敗時にほかの既存レポートまでロールバックする仕組みではない点も今回の変更による新規問題ではない。

**問い 4 — 再取り込み:** 保存済みファイルの属性検査と前回ファイル検査をどちらも実施するため、前回指摘の早期終了経路は解消している。`--allow-missing-previous` が許すのは ENOENT による不在だけで、破損や不一致は成功に変換されない。

**問い 5 — 過度の拒否:** 文字参照の記法をコード例や説明の中で引用した正当なレビューも、禁止名を含めば拒否される。実際に過去の R1 原文が新バージョンで拒否されることを回帰テストが示す。ただし、これは人間が明示的に採択した fail closed の仕様と、更新されたレビューひな形に一致する。レビュー原文から記法を言葉による説明へ変更できるため、今回独立した不具合の指摘とはしない。
