# 独立レビューの依頼文のひな形

最終更新: 2026-10-13（v0.6.0。ADR-0026。v0.6.1: 出力の形に「文字参照と HTML を使わない」〈7〉を足した）

独立レビュー（ChatGPT などのレビュアー）に渡す依頼文の決まった形。これまでの依頼文の節をそのまま決まりにし、**レビュアーの出力の形**（最後の節）を足した。返ってきたレビューは `aiqh review-import` で取り込む（ADR-0026）。出力の形の指示は、取り込みが読み落としを止めるための約束なので、変えずに使う。

## 使い方

1. 下の「ひな形」の `<…>` を埋めて、依頼文（`aiqh_<label>_r<N>_request.md`）を作る。接頭辞（`<prefix>`）はラベルごとに決める（例: `B20`、`M2-2-RI`）。回が変わっても同じ接頭辞を使う
2. `aiqh review-packet --range <from>..<to> --label <label> --request <依頼文> --zip-output <ZIP>`（変えていないが問いに要るファイルは `--doc`）でパケットを作り、依頼文の「パケットに入っているもの」を実物と照らす
3. 返ってきた原文（`independent-review-<label>-r<N>-for-claude.md`）を、収録（`docs/reviews/<label>/review-r<N>.md`。先頭に注記、後ろは原文と同一）とは別に、**受領したファイルのまま**取り込む:
   `aiqh review-import <受領したファイル> --label <label> --round <N> --id-prefix <prefix>`
   （回が 2 以上で、前の回を取り込んでいないときだけ `--allow-missing-previous`）。出力は `docs/reviews/<label>/findings-r<N>.json`（すべて `open`）。止まったら、端末の `[種類]` と行番号を見て、レビュアーに出力の形の書き直しを頼む（D3: 逃げ道は無い）
4. 状態（`resolved`・`deferred`・`accepted`・`invalid`）は、実装者が人間の承認の下で findings の JSON を直す（検査の `--check` は v2）

## ひな形

````markdown
# 独立レビュー依頼（<label> / R<N>）

あなたは独立したコードレビュアーです。このパケットは、TypeScript 製の品質ゲートツール「aiqh」の <from> から <to> への変更です。<何回目か、前の回の指摘への対応を確かめる回なら、その指摘の ID>

## 対象

- 範囲: `<from>..<to>`（<n> commit）
  - `<短い SHA>` <件名>
- <前の回の範囲、関係する版>

## 何を変えたか

<変更の要点。決定（人間の決定・ADR）の番号>

## 変えていないもの

<変えていないファイル・振る舞い。依存関係・`package-lock.json`・`tests/structure/`・禁止文字の集合など>

## 問い

1. <問い>
2. <問い>

この問い以外でも、High または Medium に当たるものに気づいた場合は、指摘してください。

## 既知の限界（再指摘は不要）

- <限界と、その記録の場所（ADR・ROADMAP）>

## パケットに入っているもの

<全文が入っているファイル（変わったファイルの数）、commit の数、`--doc` で足したファイル、Verification の節>

**入っていないもの**: <変えていないファイル・実測のスクリプトなど。見る必要があれば、その旨を書いてください（足したパケットを用意します）>

## このレビューの結果の扱い（あらかじめ決めてあります）

High・Medium が 0 なら、このレビューを終えます。Low は記録して次の版以降で扱います。

## 出力の形（取り込みのための約束です。この形のとおりに書いてください）

1. **指摘の見出し**: 指摘 1 件ごとに、見出し `### <ID>` を 1 つ（`###` の後ろに半角の空白 1 つと ID だけ。ほかの文字を付けない）。ID は `<prefix>-R<N>-<3 桁の連番>` で、`<prefix>-R<N>-001` から欠番なしにします
2. **指摘の項目**: 見出しの下に、次の 8 項目をこの順番で書きます
   - ID
   - 重要度（High / Medium / Low のどれか 1 つ）
   - 種別（バグ / 設計 / テスト / 文書のどれか 1 つ。迷うときは主なもの）
   - 対象（ファイルと行、または節）
   - 内容
   - 根拠
   - 修正案
   - 確度（確認済み / 推測のどちらか。補足は根拠に書く）
3. **全体の結論**: 節 `## 全体の結論` を 1 つ書き、その中に、件数の行を**ちょうど次の形で 1 行**書きます（指摘が 0 件のときも書きます。ほかの節には書きません）:
   `件数: High <n> / Medium <n> / Low <n>`
   続けて、全体の結論（High・Medium があるか。ないなら、そう明記する）、<前の回の指摘は解消したか>、問いへの答え、未確認範囲を書きます
4. **ID を書いてよい場所**: この回の ID（`<prefix>-R<N>-…`）は、**指摘の見出しと、その下の「ID」の項目と、下の JSON の中だけ**に書きます。ほかの文には書きません（「〜以降の ID は発行しない」のような文にも書きません）。前の回の指摘に触れるときは、前の回の ID（`<prefix>-R<N-1>-…`）を文の中で使い、ID だけの見出しにはしません
5. **JSON のブロック**: ファイルの末尾に、言語の名前を `aiqh-findings` にしたコードブロック（開きの行はちょうど ```` ```aiqh-findings ````、閉じの行はちょうど ```` ``` ````）を**ちょうど 1 つ**書きます。中身は次の形の JSON で、本文と同じ内容にします（指摘が 0 件なら `"findings": []`）。欄を足したり、値を英語にしたりしません
   ```
   {
     "schemaVersion": 1,
     "label": "<label>",
     "round": <N>,
     "summary": { "high": <n>, "medium": <n>, "low": <n> },
     "findings": [
       { "id": "<prefix>-R<N>-001", "severity": "High|Medium|Low", "kind": "バグ|設計|テスト|文書",
         "target": "…", "content": "…", "evidence": "…", "fix": "…", "confidence": "確認済み|推測" }
     ],
     "previous": [ { "id": "<prefix>-R<N-1>-001", "assessment": "解消 / 部分的に解消 / 未解消 と、その理由" } ]
   }
   ```
   `previous` は、前の回の指摘の判定があるときだけ書きます
6. **出力のファイル**: 同じ内容を `independent-review-<label>-r<N>-for-claude.md` というファイル名の Markdown ファイルとして、ダウンロードできる形で出してください（拡張子 .md、名前にパスや日本語を含めない）
7. **文字参照と HTML を使わない**: 文字参照（`&` で始まり `;` で終わる形。名前のもの・数字のもの）と、HTML のタグ・コメント（`<b>`・`<!-- … -->` など）を、本文にも JSON にも書きません。記号は文字そのものを書きます（ハイフンは `-`）。文字参照について説明するときも、`&` と `;` を付けずに名前だけを書きます（例: 「hyphen の名前付き文字参照」）。コードの中の `<` `>` `&` は、コードの書き方（バッククォート）の中に書きます
````

## 取り込みが止まる形（ADR-0026 の「止める条件」の要約）

- `aiqh-findings` のブロックが無い・2 つある・閉じていない・フェンスの形が少し違う
- JSON として不正、知らない欄、値の集合の外（英語の種別、「バグ / 文書」、補足付きの確度など）、空の項目、上限（1 件の内容などは 20,000 文字）を超える
- `label`・`round` がコマンドの指定と違う、ID の形・重複・欠番、`summary` と指摘の数が違う
- `## 全体の結論` が無い・2 つある、件数の行が無い・2 行ある・節の外にある・JSON と違う
- 見出し `### <ID>` と JSON の ID が合わない、ID だけの見出しが `### <ID>` の形でない
- 本文に、JSON に無いこの回の ID がある（全角・小文字・別のハイフンの形でも。v0.6.1: 文字参照を戻した形、HTML のコメントとタグを取り除いた形でも）
- 名前付きの文字参照が本文か JSON にある（v0.6.1。許すのは `&amp;` `&lt;` `&gt;` `&quot;` `&apos;` だけ。`;` の無い古い形のうち、ID の文字になりうる 10 個〈`sup2` など〉も止まる）。HTML のタグ・コメントそのものでは止まらない
