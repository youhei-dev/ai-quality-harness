# ADR-0014: review-packet は機械的に得た事実だけで作り、検査に通らなければ出さない

- 状態: 採用（§11 の finding とエラーの優先順位は ADR-0015 で置換）
- 日付: 2026-09-23（M2-1、v0.4.0。v0.4.1〈独立レビュー R1〉、v0.4.2〈R2〉、v0.4.3〈R3〉、v0.5.0〈M2-2: R3 の Medium 5 件〉、v0.5.37〈バックログ 17: kind symlink〉で更新）

## 文脈
M0〜M2-0 の独立レビューでは、レビューパケットを段階ごとの使い捨てスクリプト（zsh のヒアドキュメント + git コマンド）で作り、
Architecture Decisions / Verification Results / Known Risks の節を実装 AI が手で書いていた。これらの節には実装者の判断や
「すべて PASS」のような要約が入り、「AI の回答を品質保証の根拠にしない」原則と衝突する。秘密の形と生の制御文字は、
パケットを別の一時リポジトリに置いて scanner をかける、Python でバイト検査する、という手作業で確かめていた。
M2-0 R3 のパケットには、生文字を直す commit の差分として生の U+2028 / U+2029 が 1 行残った。

## 決定
1. **内容**: `aiqh review-packet --range <from>..<to>` は次だけを載せる。人間が渡した依頼文（`--request`）と前回レビュー（`--review`）、
   commit メッセージ（Co-Authored-By / Claude-Session の trailer は除去。実装 AI の説明を含み得る旨をパケットに明記）、変更ファイル一覧、
   ファイルごとの差分、`<to>` 時点の**全文**、`--doc` で指定した文書の全文、`<to>` の verify 結果（`latest.json` の `git.commit` が `<to>` で
   `dirty: false` のときだけ）。手書きの節と `--notes` は作らない。作成者の名前・メールアドレスは載せない
2. **範囲**: 両端を最初に完全 SHA に解決し、以降は SHA だけを使う。`<from>` が `<to>` の祖先でなければ exit 2（`git merge-base --is-ancestor`）。
   commit 一覧は `from..to`、差分は `git diff <from> <to>`（2 点のツリー比較、`-M50%`）。commit を含まない範囲も exit 2
3. **git の呼び出し**: シェルを経由せず引数配列で実行し、パスは `-z` で読み、内容は blob id で `git cat-file` から取る。差分はファイルごとに
   `:(literal)` pathspec で求め、利用者・リポジトリの設定で変わり得る項目（色、外部 diff、textconv、アルゴリズム、文脈行数、接頭辞、
   quotePath、relative 等）と `LC_ALL=C` / `TZ=UTC` を明示する。`core.precomposeunicode=false` も指定する（macOS の `git init` の既定 true では NFD のパスの
   pathspec が NFC に変換されて外れる。v0.4.1）。**パスの検査**（v0.4.1、M2-1-R1-001）: `-z` の出力は Buffer のまま NUL で区切り、パスごとに厳格に復号する。
   不正な UTF-8 は `invalid-utf8`、正しい UTF-8 でも LF・TAB 以外の禁止文字を含めば `raw-char`（どちらも出所 `path`、exit 1。`--exclude` した変更も対象）。
   復号できたパスだけを pathspec に使い、テキストの変更ファイルの差分が空なら exit 2（モードだけの変更・rename・空ファイルも差分ヘッダを持つため、空は pathspec の外れを意味する）
4. **変更ファイルの判定順**: `--exclude` に一致 → 除外（一覧に「excluded」と glob を記録。内容は検査も表示もしないが、blob の SHA-256 は求めて Integrity 表に載せる〈v0.4.0 SP3 #6〉）、lock ファイル → 全文・差分なし（name-status・行数なし・
   blob SHA-256）、submodule（表示する側で判定: 削除は旧側、それ以外は新側のモードが 160000。submodule → 通常ファイルの type change は通常ファイルとして扱い、
   旧側は空。status T の行は「(type change)」。v0.4.1、M2-1-R1-005）→ 内容なし、`--max-file-bytes`（既定 512 KiB）超 → exit 2（`--exclude` で明示的に除けば続行）、NUL を含む → バイナリ
   （全文・差分なし、サイズと SHA-256）、NUL を含まないが不正な UTF-8 → finding（exit 1。`--exclude` で除けば続行）、それ以外 → テキスト。
   lock ファイルはパスの最後の要素で判定し、一覧は `src/review/packet.ts` の `LOCK_FILE_NAMES` 1 か所: `package-lock.json`、`npm-shrinkwrap.json`、
   `yarn.lock`、`pnpm-lock.yaml`、`bun.lockb`、`poetry.lock`、`Pipfile.lock`、`uv.lock`、`Cargo.lock`、`Gemfile.lock`、`composer.lock`、`go.sum`。
   含めるオプションは作らない
   **v0.5.37 の補足（バックログ 17）**: 表示する側（submodule と同じ規則: 削除は旧側、それ以外は新側）のモードが 120000 のシンボリックリンクは kind `symlink`。判定は lock ファイルの名前より先（リンクの blob はリンク先のパスで、生成物ではない）。
   全文は載せず、差分（リンク先のパス）を載せて検査する。表の行数（+ / -）は出す。削除されたリンクも `symlink`（status が D）。リンク先が不正な UTF-8 なら finding（出所は `link target <path>`）。
   v0.5.36 までは、リンク先が 1 行のテキストファイルの全文として載り、kind は `text`（削除なら `deleted`、lock の名前なら `lock`）だった
5. **UTF-8**: 依頼文・レビュー原文・`--doc`・commit メッセージ・`latest.json` は不正な UTF-8 なら exit 1。変更ファイルは NUL の有無で先にバイナリを判定し、
   NUL が無ければ不正な UTF-8 は exit 1（4 の順）。`latest.json` が JSON でない、または `<to>` の結果として描画するのに形が合わない（`tool` がオブジェクト、
   `checks` がオブジェクトの配列、zod で確認）ときは、読めた文字列全体を生文字と秘密の形で検査してから出力しない判断にする（v0.5.0、M2-1-R3-003、ADR-0015）
6. **生文字の禁止集合**（`src/security/raw-chars.ts`。追跡中の Markdown を検査するテストも同じ部品を使う）: C0（TAB・LF 以外。CR を含む）、DEL、C1、
   U+2028 / U+2029、双方向制御文字（U+202A–U+202E、U+2066–U+2069）、U+FEFF（ファイル先頭の BOM も含む）
7. **検査（fail closed）**: 次の順に行う（v0.4.2 で段階を整理）。(0) **オプションの値**: パケットか ZIP に描画されるオプションの値（`--range`、`--label`、
   `--exclude`、`--doc` のパス、依頼文・レビューのファイル名、`-o` のファイル名）を、git を動かす前に生文字と秘密の形で検査する（14 の入口の一覧。
   出所は `range`・`doc path 1` などオプション名で、値は出さない。M2-1-R2-006。finding のある値は git に渡さない〈v0.5.0、ADR-0015〉）。(1) **パス**: 変更一覧と各 commit のファイル一覧のすべてのパスを、
   独立した最初の段階として検査する（不正な UTF-8・生文字・秘密の形。M2-1-R2-007。v0.5.0 から、finding のあるパスは pathspec にせず、残りの検査は最後まで続ける〈ADR-0015〉）。
   (2) **入力ごと**に、不正な UTF-8 → 生文字 → 秘密の形（共有 scanner の `scanString`）を調べる。`security.allow` は
   出所のリポジトリパスと行に適用する（差分の行は hunk から新旧ファイルの行へ対応付ける。依頼文・レビュー・commit メッセージ・verify 結果には
   パスが無いので適用しない）。aiqh が導く値（SHA、blob の SHA-256、版、時刻、status）も描画前に同じ検査を通す（14）。(3) 組み立てたパケット全体に
   生文字と秘密の形の検査をもう一度かける（行→出所の対応表で allow を適用。v0.4.2 以降、テンプレートに入る値はすべて (0)〜(2) で検査済みで、
   この段階は保険として残す）。1 件でもあれば exit 1 で、パケットも ZIP も書かない。抑止した件数と一覧は
   パケットの Integrity 節に載せる。出力は出所・行・分類またはコードポイントだけで、値・行内容・前後の文脈は出さない（`maskSecrets` / `maskDeep` も通す）。
   差分の中の finding は、差分テキストの行とファイルの行を両方出す（`diff a.ts:7 (a.ts:1)`。`<from>` にしか無い削除行は `(a.ts@from:5)`。v0.4.0 SP3 #1）。
   **安全表示**（v0.4.1、M2-1-R1-002）: review-packet が標準出力・標準エラー・`--json` に出す文字列はすべて `escapeRawChars`（`src/security/raw-chars.ts`。
   禁止文字と LF・TAB を `\u{HEX}` に）を通してから masker に通す。`--cwd`（省略時はカレント）・`--output`・`--zip-output` を解決した完全パスに禁止文字があれば
   exit 2 で、メッセージはオプション名とコードポイントだけ（ただし `-o` のファイル名そのものは ZIP のエントリ名になるため (0) の検査対象で、該当すれば exit 1。v0.4.2）
8. **書き込み**（v0.4.1、M2-1-R1-003 で 2 段階に変更）: パケットと ZIP の中身を両方メモリで作ってから、(1) 準備段階: 書き込み先が無いか通常ファイルであることを
   確かめ、両方の一時ファイル（同じディレクトリ、`.<名前>.tmp-<pid>-<乱数>`、`wx`）を書き終える。失敗したら一時ファイルを消して exit 2（既存ファイルには触れない）。
   (2) 確定段階: 既存のパケット / ZIP を退避名（`.<名前>.bak-<pid>-<乱数>`）へ rename → 新パケット → 新 ZIP の順に rename → 両方成功したら退避を削除。
   **確定点**（v0.4.2、M2-1-R2-003）は、新しいパケットと ZIP の両方を置き終えた時点とする。**確定前**の失敗では、戻し処理の各操作（新しく置いたファイルの削除、
   退避の復元、一時ファイルの削除）をすべて行い、それぞれの失敗を集める。全部成功したときだけ「the previous files were restored」と出す。1 つでも失敗したら、
   残ったファイル（`new file left at …`）・戻せなかった退避ファイル（`previous file could not be restored; it is kept at …`）・残った一時ファイルの場所を
   すべて（安全表示を通して）出し、exit 2。**確定後**の失敗（退避ファイルを削除できない）は書き込みを取り消さない: exit 0 で、標準エラーに警告と残った退避ファイルの場所を出し、
   最終行を `REVIEW PACKET: written (backup files retained)` とする（`--json` の `backupsRetained` にも一覧を入れる）。
   **同じ実体への書き込みの拒否**（v0.4.2、M2-1-R2-002。v0.4.3 で判定を変更、M2-1-R3-001）: 最終的な判定は**ファイルシステムの同一性**で行う。準備段階で
   親ディレクトリを作った後、その時点の実パスと親の `dev`+`ino` を記録し、一時ファイルをそこへ書く。確定段階（既存ファイルの退避）の直前の段階 `check:same-target` で、
   (1) 各親の `dev`+`ino` が記録と同じであること（違えば「directory changed during the write」で exit 2）、(2) 親の `dev`+`ino` が同じで basename が
   ASCII の大文字小文字を無視して同じなら同じ実体として exit 2、を確かめる（どちらも一時ファイルを消し、既存ファイルには触れない。basename は `[A-Za-z0-9._-]` に
   制限済みで、ASCII 以外なら防御として exit 2）。文字列の正規化（「親ディレクトリの realpath〈存在しなければ最も近い既存の祖先〉+ basename」を NFC・小文字にした比較）は、
   ディレクトリを作る前に分かる場合の**早い段階の拒否**にだけ使う。文字列の変換はファイルシステムの規則を写せない（v0.4.2 までは文字列だけで判定しており、APFS が
   同じ名前として扱う U+00DF / `ss`、U+03C2 / U+03C3、U+00B5 / U+03BC などの親ディレクトリ名で、同時の変更なしに既存ファイルが失われた）。大文字小文字だけが違う
   ASCII の名前は、ファイルシステムによらず拒否する（安全側）。親がシンボリックリンクを含むこと自体は拒否しない。**保証の範囲**: 判定は `check:same-target` の時点のもので、
   その後から確定までの間に他者が出力先を変更する場合は防げない（Node の標準 API には判定したディレクトリと rename するディレクトリを同じ実体に固定する `openat` 相当が無い）。
   **信頼境界**: aiqh の実行中に、出力先（`-o`・`--zip-output`）とその親ディレクトリを他のプロセスや利用者が同時に変更しないこと（README の「信頼境界」）。パケット全体が `--max-packet-bytes`（既定 4 MiB）を超えれば exit 2 で何も書かない。
   出力ファイル名は ASCII（英数字・`.`・`_`・`-`）、`--label` は英小文字・数字・`.`・`-`（1〜64 文字）
9. **再現性**: 本文に実行時刻を入れない（日時は `<to>` の committer 時刻を UTC で）。同じ範囲・同じ入力・同じ aiqh と git の版なら、パケットと ZIP は
   バイト単位で一致する
10. **ZIP**: Node 標準の `zlib.crc32` で自前に書く（新規依存なし、ADR-0008）。無圧縮（store）、固定 DOS 日時 1980-01-01 00:00:00、UTF-8 フラグ、
    Unix モード 0644。中身はパケット 1 ファイルだけ。ZIP64 は扱わない。エントリ名はパケットのファイル名で、local header と central directory の 2 か所に
    書かれ、パケットの本文ではないため 7 の (3) の検査に入らない。そのため描画前の検査（7 の (0)、`Checked` 型）を通した値だけをエントリ名にする（v0.4.2、M2-1-R2-001）
11. **終了コード**: 0 = 書いた（確定後に退避ファイルを残した場合を含む）、1 = finding があり書かない、2 = 使い方・git・上限・書込のエラー（commander の使い方エラーも 2 にする。1 は finding 専用）。
    **finding とエラーの優先順位は ADR-0015 で置換**（v0.5.0、M2-1-R3-002 / R3-003）: 検査不能（exit 2。それまでの finding を不完全な一覧として出す）→
    検出（exit 1）→ 出力しない判断（上限超過など。finding が無いときだけ exit 2）。v0.4.2〈M2-1-R2-007〉の「両方が分かっている場合は検出を先にする」は、
    オプションの値・パスの finding の後の検査不能を exit 1 に隠していた。その記録と変わった行は ADR-0015 の「R2-007 の決定との関係」にある
    **全コマンドへ広げた: ADR-0021**（v0.5.27、バックログ 11）: 使い方エラーは verify・init・security-scan と `aiqh` 本体でも 2 にする
12. **設定ファイル**: 新しいキーは追加しない。`security.allow` と窓の設定は既存の `security` セクションを使う。既定の場所は `--cwd` で指定したディレクトリ
    （省略時はプロセスのカレント）の `aiqh.config.jsonc`、`--config` で変更可。プロセスのカレントにある別リポジトリの設定を `--cwd` 先に適用しない（fail open を防ぐ。
    テストで固定、v0.4.0 SP3 #5）。リポジトリのサブディレクトリで実行した場合はルートの設定を探さない（allow が効かず、より厳しい側に倒れる）。
    `--request` / `--review` / `--config` / `-o` / `--zip-output` の相対パスは `--cwd` のディレクトリ（省略時はカレント）を基準に解決する（security-scan と同じ）
13. **Markdown の描画**（v0.4.1、M2-1-R1-004。v0.4.2 で修正）: fence の外に入る値は描画する場所ごとに関数を分ける。インラインコード（パス・glob・ファイル名・ラベル・
    JSON 由来の値）は LF・TAB・バックスラッシュを `\n` `\t` `\\`、**バッククォート（U+0060）**とその他の制御・区切り・双方向制御文字を ASCII 表記 `\u{HEX}`
    （バッククォートは `\u{60}`）に置き換えて**中身に本物の U+0060 を残さず、1 個のバッククォートで囲む**（囲みを長くする方式は採らない。CommonMark では
    コードスパンの中でバックスラッシュはエスケープにならないため、v0.4.1 の「バックスラッシュ + バッククォート」は区切りとして働いていた。M2-1-R2-005）。
    見出しにはインラインコードと固定の文字列だけを入れる。表のセルはさらに `|` を `\|` にする（commit の件名・verify の値も同じ）。SHA・版・時刻・status など
    平文で出す値は、`[A-Za-z0-9 ._:+()/-]` だけならそのまま、それ以外はインラインコードにする。描画で生文字は見えなくなるため、描画する値はすべて描画の前に検査する（7、14）
14. **検査済みの型と入口の一覧**（v0.4.2、M2-1 R2）: R2 の指摘のうち 4 件（R2-001・R2-005・R2-006・R2-007）は「列挙した経路だけ直し、別の経路が漏れた」もので、
    列挙ではなく構造で防ぐ。(a) `src/review/checked.ts` の `Checked`（brand 付きの string）は、描画前の検査（生文字と秘密の形）を通ったことを表し、
    検査関数 `checkValue` が作る。**保証**（v0.5.0、M2-1-R3-004。v0.4.3 までは型と `as Checked` の文字列検査だけで、`any`・型の別名・`JSON.parse` の代入などで迂回できた）:
    型に加えて 2 つで固定する。① 型情報付きの構造テスト（`tests/structure/brand-guard.ts`、TypeScript コンパイラ API。別名・`typeof`・`Parameters<>` も同じ型に解決する）:
    brand を作れるのは `checked.ts` の `issue` と `REJECTED`、`packet.ts` の `issueMd` だけで、`issue` は `checkValue` だけが、`issueMd` は描画関数だけが呼ぶ。
    brand・`any`・`never`・引数に現れない型引数への型アサーション、brand への型ガード、`any` の brand への流入、描画関数を素の文字列の関数として渡すこと、
    brand を含む入れ物を書き込める素の型へ広げること、`@ts-` 指示、`md` のタグ以外の使い方を報告する。② 実行時の登録簿: `checkValue` を通った文字列と
    描画関数が作った `Md` をプロセス内で登録し、描画関数・`md`・組み立て（`Builder`）・ZIP のエントリ名が登録を確かめる（無ければ `UncheckedValueError`、exit 2）。
    残る限界: 登録済みと同じ内容の文字列は通る（その内容は検査済み）。登録簿はプロセスの中で増える一方。規則に無い型の穴は構造テストで見つからないが、実行時の確認で止まる。
    描画関数を素の文字列を取る関数型へアサーションしてから呼ぶ形（`as (s: string) => Md`、`as unknown as …`、型の別名）は、規則 `widened-renderer` で検出し、
    v0.5.28 で回帰テストの fixture（`regression-m2-2-builtin-r3-allow-branches.test.ts` の群 `FA`）を足した（M2-2-R1-004）。同じ版で、それまで見逃していた 3 形
    （名前空間のメンバー `PKG.inlineCode`、オブジェクトのプロパティ `o.r`、引数が `string | Checked` の関数型）も検出するようにした（`tests/structure/brand-guard.ts`:
    プロパティ・要素アクセスにも識別子と同じ判定を適用し、文脈の関数型が素の文字列を受ける場合を報告する。報告を増やす側だけで、型で新たに許可する経路は足していない。

    `plainOrCode`）と ZIP のエントリ名は `Checked` だけを受け取る。(b) パケットの本文は `md` タグ付きテンプレートで組み立て、埋め込めるのは描画関数を通した

    解析・出力・シグナルの登録・終了をしない（`src/cli.ts` が版の読込・シグナル・解析を行う）

## 代替案
- 差分だけを載せる（ROADMAP の当初案）: レビュアーが変更の前後関係を追えない。全文を載せる
- 検出した値をマスクして出す: レビュー対象のコードを書き換えることになり、何が隠れたかも分からない。出さない（fail closed）
- 生文字を可視の記号に置き換える `--escape-raw`: 置換が内容の忠実さを損なう。作らず、必要なら `--exclude` と依頼文での説明で扱う
- OS の `zip` コマンド: Linux で未導入のことがあり、Windows には無く、mtime が入る。自前で書く
- deflate 圧縮: 出力が zlib の版に依存し得る。store にする

## 影響
- 生文字を直す commit（M2-0 R3 の例）はそのままではパケットにできない。該当ファイルを `--exclude` し、依頼文で説明する
- CRLF のファイル、BOM 付きのファイルを含む範囲はパケットにできない（exit 1）。`--exclude` で除く
- パケットの作成に git 2.x が必要。出力の再現性は git の版に依存する（git の版をメタデータに記録する）
- 本体リポジトリ自身の追跡中 Markdown は、広げた禁止集合でも 0 件（54 ファイル、v0.4.0 時点）
- **信頼境界**（v0.4.3）: aiqh の実行中に、出力先（`-o`・`--zip-output`）とその親ディレクトリを他のプロセスや利用者が同時に変更しないこと。同じ実体の判定（8）は確定の直前の時点のもので、それ以降の同時の変更は防げない
