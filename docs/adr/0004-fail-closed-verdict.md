# ADR-0004: 最終判定は fail closed とし、必須チェック 0 件を許さない

- 状態: 採用
- 日付: 2026-09-15

## 文脈
Quality Gate は「AI が問題ないと言った」ことを根拠にせず、機械的な結果だけで判定する。
通らなかった理由が何であれ、通らなければ止まるべきである。

## 決定
1. 最終判定 `PASSED` は「`required: true` の全 check が `PASS`」のときのみ。それ以外は `FAILED`
2. `FAIL` の定義: 終了コード非ゼロ、タイムアウト、起動失敗（コマンド不在・cwd 不在）、シグナル終了
3. `SKIPPED`（`--fail-fast` により未実行）は必須 check では `PASS` ではないため `FAILED` になる
4. 任意 check（`required: false`）の `FAIL` は判定に影響しないが、レポートには `FAIL` として残す
5. 設定に `required: true` の check が 0 件の場合は設定エラー（終了コード 2）。「常に PASS する設定」を作れないようにする
6. 設定不正・レポート書込失敗・予期しない例外はすべて終了コード 2（非ゼロ）
7. 既定では失敗しても全 check を実行し、全体像を 1 回で報告する。`--fail-fast` は明示指定のみ

## 根拠
- 「通らなかった理由」を区別しても、CI のゲートとしては非ゼロで止めることが最優先
- 任意 check を残す理由は、導入直後のツール（例: 新規追加した security scan）を「様子見」として走らせつつ、
  結果を可視化して必須化の判断材料にするため

## 代替案
- 分類ごとに警告と失敗を分ける（lint の warning 等）: 分類はコマンドの終了コードに委ねる。
  ESLint の `--max-warnings 0` のように、ツール側で厳しさを決める

## 影響
- テストで「必須 1 件失敗 → FAILED / 終了コード 1」「任意失敗 → PASSED」「必須 0 件 → 設定エラー」を固定する
