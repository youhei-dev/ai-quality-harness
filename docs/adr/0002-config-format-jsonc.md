# ADR-0002: 設定ファイル形式を JSONC にする

- 状態: 採用
- 日付: 2026-09-15

## 文脈
設定ファイルの要件は「機械可読でスキーマ検証できる」「人間がコメントを書ける」
「チェックごとに名前・コマンド・作業ディレクトリ・必須／任意・タイムアウトを持てる」
「Node 系と Python 系を同じ形式で扱える」「秘密情報を一切含まない」。

## 決定
`aiqh.config.jsonc`（JSON + コメント + 末尾カンマ）を採用する。読込は `jsonc-parser`、
検証は `zod` のスキーマで行い、未知のフィールドはエラーにする。M1 で zod から JSON Schema を
生成して同梱し、エディタ補完・検証を可能にする。

## 根拠
| 候補 | コメント | スキーマ検証 | 暗黙の型変換 | 備考 |
|---|---|---|---|---|
| JSON | ✘ | ◎（JSON Schema） | なし | コメント不可のため要件を満たさない |
| **JSONC** | ✔ | ◎（JSON Schema をそのまま流用） | なし | `tsconfig.json` / VS Code 設定と同じ習慣。Python 開発者にも JSON は馴染みがある |
| YAML | ✔ | ○（変換して JSON Schema） | あり（`no` → false、`1.10` → 1.1 等） | インデント事故と暗黙変換が設定ミスの温床 |
| TOML | ✔ | ○ | 少ない | 配列オブジェクトの表記が冗長。Node 標準パーサなし |
| `aiqh.config.ts` | ✔ | ◎（型） | なし | **実行可能な設定**になり、設定読込時に任意コードが動く。Quality Gate の設定としては不適切 |

秘密情報の排除は形式ではなく**スキーマ**で担保する。設定にはコマンド文字列と構造化フィールドしか置けず、
環境変数の値を書くフィールドを用意しない。

## 代替案
YAML は人気があるが、fail closed のツールでは「書いたつもりの値と違う値で通る」暗黙変換を避けたい。

## 影響
- 依存に `jsonc-parser` と `zod` を追加する
- 設定ファイルはコメントが書けるので、「なぜこの check を任意にしたか」を設定内に残せる
