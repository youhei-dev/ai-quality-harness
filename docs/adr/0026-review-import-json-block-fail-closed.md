# ADR-0026: review-import は、レビューの中の決まった JSON のブロックを正本にし、本文と食い違えば何も書かない

- 状態: 採用（M2-2 の本体〈ROADMAP の項目 15、rest2 の計画の波 3〉の最初の部品。ARCHITECTURE の review-import の出力の置き場所〈`artifacts/ai-review/findings-<id>.json`〉を置き換える。ADR-0007〈artifacts は git 管理外〉は変えない。v0.6.1 で、独立レビュー R1 の 3 件を受けて、決定 13〜17〈名前付きの文字参照の拒否、数値の文字参照の戻し方、HTML の除去、`writeAtomic` の一時ファイル、同じ原文の再取り込みの検査〉を足した〈下の「追記（v0.6.1）」〉。R2〈指摘なし〉の後に、この検査の前提〈脅威モデル〉を決定 18 として足した〈下の「追記（R2 の後）」〉）
- 日付: 2026-10-13（v0.6.0）。追記: 2026-10-13（v0.6.1。独立レビュー R1 の M2-2-RI-R1-001〜003。決定 13〜17、使い方の `--cwd` の相対パスの一文、端末への出力の種類 `entity`、既知の限界の一時ファイルの名前）、2026-10-13（R2 の後。docs だけで、版は 0.6.1 のまま。決定 18〈この検査の前提〉、R2 の結果、v0.6.1 の既知の限界の位置づけの注記）

## 文脈
- `aiqh review-import` は、独立レビューの原文を読み込み、指摘を構造化したデータ（findings）にする。**一番の危険は読み落とし**で、指摘を 1 件でも取りこぼすと「レビューは終わった」と誤って判断する（fail open）
- 波 3 の SP1（2026-10-13）で、`docs/reviews/` の原文 47 件を調べた。依頼文が「指摘の形式」を指定していたのは 11 回だけで、指定した回でも、要約の置き場所・書き方が揺れていた（厳しい読み取りで読めたのは 47 件中 6 件、指定した 11 回でも 6 回）。fail open になりうる形として、要約が一部の重要度に触れない（6 件）、要約が無い（6 件）、同じ ID の見出しが参照としてもう一度出る（1 件）、指摘ではない位置のその回の ID（例: 「`B35-R1-001` 以降の指摘IDを発行する事項はない」）、前の回の ID を含む見出し、が見つかった
- 人間の決定（2026-10-13）: SP1 の 12 項目をすべて推奨どおりにする。直した指摘の状態の名前は `resolved`。v1 の独立レビューは、新しい依頼文のひな形で行い、返ってきた結果を v1 で取り込んでみる

## 決定
1. **D1 入力の正本**: レビューの md の中の、言語の名前を `aiqh-findings` にした**コードブロック 1 つ**の JSON（下のスキーマ）。本文（ブロックの外のすべての行）の `### <ID>` の見出しと、`## 全体の結論` の件数の行で突き合わせる。ファイルは 1 つのまま（これまでの「ダウンロードできる md」の作法と同じ）
2. **D2 読めない・食い違うとき**: **exit 2 で、何も書かない**。警告して続けることはしない。見つかった食い違いはすべて並べる（1 つずつ直させない）
3. **D3 逃げ道なし**: 「指摘ではない ID」を認めるオプションは作らない。止まったらレビュアーに書き直しを頼む
4. **D4 状態**: `open`・`resolved`・`deferred`・`accepted`・`invalid` の 5 つ。「未完了」= `open` が 1 つでもある
5. **D5 状態の正本**: findings の JSON。実装者が人間の承認の下で直す。検査（`--check`）は v2
6. **D6 置き場所**: **`docs/reviews/<label>/findings-r<N>.json`（git 管理）**。原文・対応記録の隣。ARCHITECTURE の `artifacts/ai-review/findings-<id>.json` から変える（状態は回をまたぐ記録で、git 管理外では失われる）
7. **D7 終了コード**: **0 / 2**。`open` の件数は端末に表示するだけで、終了コードに反映しない（非目標「レビューAI の判断を自動で合否に反映すること」に当たらないように）。1 は使わない
8. **D8 前の回**: 回が 2 以上で、`findings-r<N-1>.json` が無い（**ENOENT だけ**）ときは exit 2。`--allow-missing-previous` でだけ許す。ENOENT 以外の理由で読めない（EACCES・ディレクトリ・不正な JSON・スキーマ違反・label / 回 / 接頭辞の違い）ときは、オプションがあっても exit 2（ADR-0022）
9. **D9 禁止文字**: 止めずに取り込み、ファイルでは表記にする（ADR-0020。JSON は `\uXXXX`）。端末には件数と行番号だけ
10. **D10** 過去の 47 件は取り込まない
11. **D11 v1 の範囲**: 取り込みだけ。状態の検査・前の回の状態の引き継ぎ・ループ未完了の表示は v2
12. **D12 依頼文のひな形**: `docs/ops/review-request-template.md`。JSON の欄を足す（v1 自身の独立レビューが最初）

### 使い方
`aiqh review-import <review.md> --label <label> --round <n> --id-prefix <prefix> [--allow-missing-previous] [--cwd <dir>]`
- `--label`: `docs/reviews/<label>/` の名前。英小文字・数字・`.`・`-`（先頭と末尾は英数字、64 文字まで、`..` は不可）。パスの区切りは通らない
- `--round`: 1〜999 の整数（0 や数でないものは使い方の誤り）
- `--id-prefix`: 英大文字・数字のまとまりを `-` でつないだもの（`B20`、`M2-2-RI`）。ID は `<prefix>-R<round>-<3 桁>`
- `--cwd`: `docs/reviews/` のあるリポジトリのディレクトリ（既定: カレント）。ほかのコマンドと同じ。`docs/reviews/` が無いディレクトリでは止める（サブディレクトリで走らせて別の場所に書くことを防ぐ）。**`<review.md>` を相対パスで書いたときは、`--cwd` のディレクトリ（省略時はカレント）を基準に解決する**（v0.6.1 で明記。v0.6.0 から同じ動き）
- 出力のパスは `resolveInsideRoot` で、リポジトリの中に収まることを確かめる（symlink で外へ出るものは止める）

### 入力の JSON（schema version 1）
```
{ "schemaVersion": 1, "label": "<label>", "round": <n>,
  "summary": { "high": <n>, "medium": <n>, "low": <n> },
  "findings": [ { "id", "severity": "High|Medium|Low", "kind": "バグ|設計|テスト|文書", "target", "content", "evidence", "fix", "confidence": "確認済み|推測" } ],
  "previous": [ { "id", "assessment" } ] }   ← previous は任意
```
- 未知の欄は拒否する（どの深さでも）。8 項目はどれも空白だけの値を認めない
- `kind`・`confidence` は**日本語の値だけ**（英語の別名は認めない。依頼文の作法のとおりで、迷う形は拒否する）。**1 つだけ**（「バグ / 文書」のような 2 つは拒否。主なものを選び、補足は `evidence` に書く）。`confidence` に補足を付けた形（「確認済み（一部）」）も拒否
- 上限（細部の決定）: 入力のファイル **1 MiB**、`findings` と `previous` は各 **200 件**、`id` **64 文字**、`target` **2,000 文字**、`content`・`evidence`・`fix` 各 **20,000 文字**、`assessment` **4,000 文字**、`label` **64 文字**、回 **999**。保存した findings のファイルでは、マスクで文字列が伸びうるので、文字列の上限を入力の 2 倍にする

### 止める条件（すべて exit 2、何も書かない）
- **入力のファイル**: 無い・読めない・通常のファイルでない（symlink は先を見る）・1 MiB を超える・不正な UTF-8（行番号を出す）
- **ブロック**: `aiqh-findings` の開きのフェンス（行が **ちょうど** `` ```aiqh-findings ``）が 0 個・2 個以上。ほぼ同じ形のフェンス（`` ```aiqh-findings json ``・大文字・`~~~`・空白入り）。閉じのフェンス（行がちょうど `` ``` ``）が無い
- **JSON**: JSON として不正、スキーマ違反、`label`・`round` がオプションと違う、ID の形が `--id-prefix` と回に合わない、ID の重複、001 から連続でない、`summary` と重要度ごとの数が違う
- **本文**: `## 全体の結論` が 0 個・2 個以上。その節の中の `件数: High <n> / Medium <n> / Low <n>`（ちょうどこの形の 1 行）が 0 行・2 行以上、**節の外にある**、数が JSON と違う。`### <ID>`（ID だけの見出し）の集合が JSON の ID の集合と違う（同じ見出しが 2 つも）。**ID だけの見出しなのに `### <ID>` でないもの**（`## <ID>`、空白 2 つ、別の回の ID だけの見出し〈`### B20-R1-003` を R2 で〉）。本文のどこかにある**その回の ID の形**（`<prefix>-R<round>-<数字>`。全角・小文字・`‐` などのハイフンの形は寄せて探す: NFKC と、ハイフンに似た文字を `-` に、英字を大文字に）が JSON に無い
- **前の回と既存のファイル**: 上の D8。出力のファイルが既にあり、`source.sha256` が入力と違う（同じなら何も書かずに exit 0「既に取り込み済み」）。既存のファイルが読めない・findings のファイルでない
- **その他**: 使い方の誤り（ADR-0021）、`docs/reviews/` が無い、パスがリポジトリの外、書き込みの誤り
- 前の回の ID に文を付けた見出し（`### B20-R1-001 の判定`）は止めない（前の回の指摘の判定で、新しい指摘ではない）。JSON にある ID を本文の文の中で書くことも止めない
- 構造の行（フェンス・見出し・件数の行・節）は、行末の CR 1 つを除いて読む（CRLF で保存したレビューも同じに読む）

### 出力（`findings-r<N>.json`）
- 欄: `schemaVersion: 1`、`label`、`round`、`idPrefix`、`source`（受領のファイル名〈名前だけ〉・バイト数・SHA-256）、`summary`、`previous`（入力のまま。無ければ `[]`）、`importedAt`（ISO 8601）、`tool`（`{ name: "aiqh", version }`。verify のレポートと同じ形）、`findings`
- `findings` の各件: 入力の 8 項目（ID の順に並べる）、`status: "open"`、実装者の側の欄 `verdict`・`action`・`fixedIn`・`regressionTest`・`guard`・`destination`・`note` は `null`（形は v2 で決める）。M0_COMPLETION の review-import の表の列（ID / 重要度 / 判定 / 対応 / 根拠・修正内容 / 回帰テスト / ガード / 行き先）は、これで全部持てる
- 書き方: 文字列はすべて `copyJson(…, maskSecrets)` を通す。書き込みは verify のレポートと同じ `writeAtomic`（一時ファイル → rename。JSON は書き込みの直前に禁止文字を `\uXXXX` に）。UTF-8、末尾は LF。`docs/reviews/<label>/` が無ければ作り、書き込みに失敗したら消す
- **`writeAtomic` の変更**（v0.6.0）: 書き込みか rename に失敗したとき、一時ファイルを消してから誤りを投げる（以前は残った）。verify のレポートの書き込みにも同じに効く。書き込み箇所の表（`tests/file-write-sites.test.ts`）の行は変わらない（新しい fs の書き込みは足していない）

### 端末への出力
- 出口（`createOutput`）だけを通す。レビュアーの文章は出さない（未知の欄の名前・誤った値も出さない。スキーマの誤りは、この形の欄の名前と配列の番号だけ）
- 成功: `findings: docs/reviews/<label>/findings-r<N>.json`、`High <n> / Medium <n> / Low <n>; open <n>`、`REVIEW IMPORT: written`。禁止文字があれば件数と行番号。秘密の形を `scanString` で見つけたら、件数・分類・行番号（保存した文字列はマスク済み。取り込みは続ける）
- 誤り: `aiqh review-import: [<種類>] <説明>`（種類: `options`・`repository`・`path`・`input`・`existing`・`block`・`json`・`schema`・`label-round`・`id`・`summary`・`conclusion`・`count-line`・`heading`・`id-mention`・`previous`・`write`。v0.6.1 で `entity` を足した〈決定 13〉）を並べ、最後に `REVIEW IMPORT: not written (error)`

## 代替案
- **入力の正本 (a) いまの Markdown の形式を厳しく読む**: 依頼が変わらないが、SP1 では形を指定した回でも 5/11 が要約の置き場所・書き方の揺れで読めなかった。規則を足すほど読み方の抜けが増える
- **(c) Markdown と JSON の両方を受け付ける**: 過去のレビューも取り込めるが、読み方が 2 つになり、テストと抜けの面が倍になる
- **状態の正本 (i) `response-rN.md` の判定表**: 表の列が 22 通りで揃っていない。(iii) 状態を変える専用のコマンド・(iv) JSON から判定表を生成: 使ってから（v2 以降）
- **置き場所 `artifacts/ai-review/`**: git 管理外で、回をまたぐ状態が残らない
- 読めないときに警告して続ける: 読み落としがそのまま「終わった」になる
- 本文から JSON を組み立てる（JSON をレビュアーに書かせない）: (a) と同じ揺れの問題

## 既知の限界
- **ID を書かず、件数の行にも JSON にも入れずに、文章の中だけで書かれた指摘は見つけられない**。突き合わせは「JSON・見出し・件数の行・本文の ID が互いに合うか」で、レビュアーが書いたものを全部読み取れたかの証明ではない
- ID に似た字形のうち、NFKC とハイフンの寄せで同じにならないもの（キリル文字の `Р` など）は、その回の ID として見つけない
- 本文の ID の形の探し方は、接頭辞の前が英大文字・数字・`-` でないことを条件にする（`QB20-R1-001` は `B20` の ID ではない）
- D3 のとおり、指摘ではない文脈でその回の ID を書いたレビューは止まる（書き直しを頼む）
- v2 の範囲（`--check`、前の回の状態の引き継ぎ、ループ未完了の表示）は無い。`previous` は保存するだけで、前の回の状態は変えない
- 過去の 47 件は取り込まない（D10）
- 同じ出力先へ同時に取り込むことは考えていない（一時ファイルの名前はプロセスの番号で分ける。v0.6.1 で変更: ランダムな名前を排他的に作る〈決定 16〉）。「既に取り込み済み」の確かめと書き込みのあいだに別の手が書くことは信頼境界の外
- 秘密の形のマスクは ADR-0006 の範囲のまま（マスクのパターンに無い形は残る）

## 追記（v0.6.1: 独立レビュー R1 の 3 件。M2-2-RI-R1-001〜003）

### 文脈
- v0.6.0 の独立レビュー R1 は Medium 3（High 0・Low 0）。3 件とも VALID（人間の判断）
  - M2-2-RI-R1-001: その回の ID を HTML の名前付き文字参照（`hyphen` などの名前に `&` と `;` を付けた形）で書くと、ID として検出されず、本文に隠れた指摘が findings から漏れて exit 0 になりうる（fail open）
  - M2-2-RI-R1-002: `writeAtomic` の一時ファイルの名前（`<target>.tmp-<pid>`）が予測でき、排他的に作らないので、その名前のシンボリックリンクを追ってリポジトリの外を書き換えうる
  - M2-2-RI-R1-003: 同じ原文の再取り込みが、前の回のファイルの確認と、既存のファイルの label・round・接頭辞の照合を飛ばして exit 0 になる
- 人間の決定（2026-10-13）: (1) 001 は、名前付きの文字参照があれば止める（許すのは `&amp;`・`&lt;`・`&gt;`・`&quot;`・`&apos;` だけ）。ひな形でレビュアーに文字参照を使わないよう頼む。(2) 同じ種類の穴の予防として、ID を探す前に HTML のコメントとタグを取り除く（止めはしない。`Array<string>` のような型の書き方を止め過ぎるため）。002 の書き方は B-2（下の決定 16）。既存テスト `tests/review-import.test.ts` の「一時ファイルの名前がディレクトリに取られて書き込みが失敗する」テストは A-1（期待値の行は変えず、塞ぎ方だけを新しい名前に合わせる。乱数の固定は、テストのファイルの中で `node:crypto` を差し替える）
- R1 の原文は、説明の中で文字参照を使っているので、直した後の版では `[entity]` で止まる（それが正しい。取り込みは直す前の v0.6.0 で行った。テストで固定）

### 決定 13: 名前付きの文字参照（M2-2-RI-R1-001、人間の決定 1）
- `&` + 英字で始まる英数字 + `;` のうち、`&amp;`・`&lt;`・`&gt;`・`&quot;`・`&apos;` 以外（大文字の `&AMP;` なども）が、どの行（JSON のブロックの行を含む）にあっても、JSON を解析した後の文字列（JSON のエスケープで書いた形）にあっても、**exit 2・何も書かない**。新しい種類 `[entity]` で、行番号だけを出す（参照の名前・文章は出さない）
- 許した 5 つは、ID を探す前に、数値の参照と 1 回の置き換えで戻す（戻した `&` から別の参照は作らない）
- **セミコロンの無い古い形（legacy）**: CommonMark 0.31.2 の §2.5 は、文字参照を「`&` + HTML5 の名前 + `;`」とし、HTML5 が `;` の無い一部の形（`&copy` など）を受け付けることについて「文法があいまいになるので、ここでは認めない」と書いている（仕様の本文で確かめた。2026-10-13）。一方、ブラウザは生の HTML の中では 106 の legacy の名前を `;` なしでも戻す。そこで**固定の一覧で止める**: 戻した文字が寄せ（書式文字の除去・NFKC・ハイフン類を `-`・大文字）の後に ID の文字（英大文字・数字・`-`）を含むか、何も残らない 10 個（`frac12`・`frac14`・`frac34`・`ordf`・`ordm`・`shy`・`sup1`・`sup2`・`sup3`・`szlig`。Python 3.14.7 の `html.entities.html5` の表から計算）。残りの 96 個は ID の文字にならないので通す（`&copy 2026` は止めない）。後ろに英数字と `;` が続けば、上の名前付きの参照として扱う

### 決定 14: 数値の文字参照の戻し方（細部の決定。理由をここに書く）
- ブラウザの読み方に合わせる: `;` が無くても戻す（`&#45R1`）、数字はすべて読む（`&#45002` は 1 つの数）、128〜159 は HTML の規格の表で windows-1252 の文字にする（`&#150;` は en dash、`&#151;` は em dash、`&#153;` は商標の記号で NFKC の後は `TM`）。0 と U+10FFFF を超えるものは、これまでどおり取り除く（つながって ID に見えれば止まる側）
- 理由: legacy の名前（決定 13）と同じ種類の穴（生の HTML の中でブラウザが戻す形）を、同じ考え方で閉じる。CommonMark（§2.5: 10 進は 1〜7 桁、16 進は 1〜6 桁、`;` が要る）より広く戻すが、広く戻すほど ID が見つかる側（止める側）にしか働かない。表と読み方は Python の `html.unescape` で確かめた。人間の決定の「数値の文字参照は、いまのとおり戻す」の範囲の細部として決めた

### 決定 15: HTML のコメントとタグ（人間の決定 2）
- ID を探す前に取り除く。**止めはしない**（取り除いた後に ID が現れれば、ほかの規則〈`id-mention`〉で止まる）。取り除くのは「その回の ID を探す」ときだけで、見出し・件数の行・ID の項目など、構造を読む規則は変えない
- 各行と、JSON を解析した後の各文字列を、**書いたとおり**と、次の **2 つの形**の計 3 通りで探す（細部の決定）:
  - (a) CommonMark 0.31.2 の §6.6（Raw HTML）が HTML として読むもの（仕様の本文で確かめた。2026-10-13）: 開きタグ（属性。引用符で囲んだ値は `>` を含みうる）、閉じタグ、コメント（`<!-->`・`<!--->`、または最初の `-->` まで。ブラウザが終わりとする `--!>` でも終える）、処理命令（`?>` まで）、宣言（`<!` と英字から `>` まで）、CDATA（`]]>` まで）。左から順に読み、どれでもない `<` は文字。空白は仕様（空白・タブ・改行 1 つ）より広く `\s` で読む（広く読むほど取り除く側）
  - (b) 局所の形: `<` と `>` を含まない `<…>` のすべて。ブラウザが落とすが CommonMark は HTML として読まない形（`<?x>`・`</>`・`</ x>`・`<b ="x>`）と、(a) が手前の `<`（コードの中の `a<b` など）で読み違えたときの補い
- 取り除き過ぎても、書いたとおりの形も探すので、見落としは増えない（止める側に寄るだけ）。複数行にまたがる部分を取り除いても、ほかの行の行番号は変わらない（取り除いた部分の改行は、その始まりの行の後ろに置く）
- 線形の時間: (a) は、閉じの文字列（`-->`・`--!>`・`?>`・`]]>`・`>`）が一度見つからなければ以後探さない。開きタグの正規表現は、名前・値の文字の集合が重ならないので後戻りが増えない。手元の計測（`readReview`、Node 24.13.1、各 1 回）: `<!--`・`<a b="`・`<?`・`<!x`・`<a `・`<![CDATA[` などの繰り返しの本文で、256 KiB が 8〜20 ms、1 MiB が 30〜58 ms
- 実験の版（v0.6.1 の前、commit していない）の 1 つの正規表現は、引用符の中の `>`、`<!-->`、`>` を含み `--!>` で終わるコメントで ID を漏らしたので、この形にした

### 決定 16: `writeAtomic` の一時ファイル（M2-2-RI-R1-002、人間の決定 B-2）
- **名前**: 同じディレクトリの `.<元の名前>.tmp-<16 桁の 16 進数>`（`node:crypto` の `randomBytes(8)`。`node:crypto` は出力の境界のガード〈`tests/structure/output-guard.ts` の組み込みモジュールの一覧〉に入っている）
- **作り方**: `O_WRONLY | O_CREAT | O_EXCL | O_NOFOLLOW` で排他的に作り、すぐ閉じる。名前が既にあれば（ファイル・ディレクトリ・シンボリックリンク、壊れたリンクも）開かず、別の名前で計 5 回まで試す。5 回とも EEXIST なら EEXIST を投げ、何も置き換えない
- **書き方**: その名前を、数値の flag `O_WRONLY | O_TRUNC | O_NOFOLLOW`（`O_CREAT` なし。作成しない）で開き直して書き、rename する。作ってから開き直すまでのあいだに名前がシンボリックリンクへ差し替えられていれば **ELOOP**（リンクの先は変わらない）、名前が消されていれば **ENOENT**（何も作らない）。どの失敗でも、自分が作った名前だけを消して（差し替えられたリンクは名前ごと消える。リンクの先は消さない）誤りを投げる。review-import は `[write]` で exit 2、何も書かない
- **型の変換（1 か所だけ）**: `@types/node` の `writeFileSync` の `flag` は文字列の型だけなので、数値の flag を `as unknown as string` で渡す（`src/report/write.ts` の `REOPEN_FLAG`。理由をその行のコメントに書いた）。Node の実行時は数値の flag を受け付ける（Node 24.13.1 で、通常のファイルには書け、リンクは ELOOP、無い名前は ENOENT になることを確かめ、テストで固定した）。文字列の flag には O_NOFOLLOW を表す文字が無いので、リンクを追わないためには数値の flag が要る
- **B-1 を採らなかった理由**: 開き直しを文字列の `"r+"` にすると、閉じてから開き直すまでのあいだにリンクへ差し替えられた名前を追う（リンクの経路が残る）
- **B-3 を採らなかった理由**: 作ったときの fd にそのまま書く形は、出力の境界のガードの「`src/` は fs の書き込みを数値（fd）へ向けない」規則（`tests/structure/output-guard.ts`、ADR-0019）に当たる。規則を緩めると `src/` の全体で fd への書き込みが静的に止まらなくなる（ガードの緩和は、それ自体の ADR と承認が要る）。B-2 は規則を変えずに、リンクの経路を閉じる
- **Windows（`O_NOFOLLOW` が無い）**: `fs.constants.O_NOFOLLOW` が無いときは 0 にする。名前のランダム化と排他的な作成（`O_EXCL`）は残るが、作成でも開き直しでもリンクを拒まない（Windows でシンボリックリンクを作るには、権限か開発者モードが要る）。Windows での動きは確かめていない（CI の `measure (windows)` は手動の実行だけ。ADR-0025）
- verify のレポート・履歴にも同じに効く。名前・中身・書き込みの失敗の exit 2 は変わらない（回帰テスト）。書き込み箇所の表（`tests/file-write-sites.test.ts`）と `tests/structure/` は変えていない（中身の式と書き込みの関数は同じ）
- 既存テスト（人間の決定 A-1）: `tests/review-import.test.ts` の「一時ファイルの名前がディレクトリに取られて書き込みが失敗する」テストは、期待値の行（exit 2・`[write]`・何も足さず、そこにあったものは残る）を変えず、塞ぐ名前だけを `.findings-r1.json.tmp-<固定の 16 進数>` にした（このテストの中だけ `randomBytes` を固定。ファイルの先頭で `node:crypto` を、既定では本物を通す形に差し替える。`src/` にテスト専用の入口は足していない）

### 決定 17: 同じ原文の再取り込み（M2-2-RI-R1-003）
- 既存のファイルの `source.sha256` が入力と同じでも、(1) 既存のファイル自身の `label`・`round`・`idPrefix` がオプションと同じか（違えば `[existing]`）、(2) 前の回の検査（決定 8 と同じ規則: ENOENT は `--allow-missing-previous` のときだけ通す。読めない・スキーマ・label / round / 接頭辞の違いは止める。違えば `[previous]`）を通してから exit 0「既に取り込み済み」。どちらも exit 2、何も書かない。前の回の検査は 1 つの関数にまとめ、新しい取り込みと再取り込みの両方で呼ぶ

### 採らなかった案
- 001 でタグを見つけたら止める: `Array<string>`・`Map<K, V>` のような型の書き方を止め過ぎる（人間の決定 2）
- legacy の名前をすべて止める（106 個）: `&copy 2026` のような ID と関係の無い形まで止める。ID の文字にならない 96 個は、取り込みの穴にならない
- HTML の除去を 1 つの正規表現で行う（実験の版）: 決定 15 の最後の項のとおり漏れがあった
- 002 の B-1・B-3: 決定 16 のとおり

### 既知の限界（v0.6.1 で足したもの）
- **ID を探すときに、表示のされ方を全部は再現しない**。文字参照（決定 13・14）と HTML のマークアップ（決定 15）は取り除くが、次は扱っていない（v0.6.1 の時点。扱うかは人間の判断。R2 の後で注記: 人間の決定で、決定 18〈この検査の前提〉の下での既知の限界とした。わざと ID を隠す書き方への備えは、この検査の目的の外）:
  - 要素の意味・属性・CSS で隠れる中身（`hidden` 属性、`display:none`、`<script>`・`<style>` の中身）。マークアップは取り除くが、中身の文字は残す（ID の途中に隠れた文字を挟むと、その回の ID として見つけない）
  - Markdown のリンク・画像の書き方で ID を分けた形（`[` `]` `(…)` は取り除かない。強調とコードの印〈`*` `_` バッククォート `~`〉は v0.6.0 から取り除く）
  - (a)・(b) のどちらとも違う読み方をブラウザがする壊れた HTML（引用符の中に `>` がある属性を、(a) が手前の `<` で読み違えたあとに置く、など）
- **`writeAtomic` の開き直しまでの隙のうち、ハードリンク**: 作ってから開き直すまでのあいだに、同じディレクトリへ書ける者が名前をハードリンクや別の通常のファイルに差し替えると、`O_NOFOLLOW` では止まらず、その中身を書き換える（ハードリンクの先が同じファイルシステムの別の場所のファイルなら、そのファイルが変わる）。名前は事前に分からず、差し替えには監視が要る。同時に動く別の書き手は信頼の境界の外（ADR-0014 と同じ扱い）
- **Windows**: 決定 16 のとおり、リンクを拒まない。動きは確かめていない
- 一時ファイルの名前はランダムなので、強制終了で残った一時ファイルは、次の実行で消えない（v0.6.0 までと同じく、残ったものは手で消す。名前は `.<元の名前>.tmp-` で始まる）
